n8n Set Node Data Type Mismatch — Fix

Error: value is not of expected type · Node: Set

What this error actually means

When you encounter the "value is not of expected type" error in n8n, it means that the node you're using (in this case, the Set node) is expecting a specific data type for a field, but it's receiving a different type instead. This can happen when you're trying to set a field to a value that doesn't match the expected type.

For example, if you have a field set to "number" and you're trying to set it to a string value, n8n will throw this error. Similarly, if you have a field set to "boolean" and you're trying to set it to a number value, you'll get the same error.

The three most common causes

Based on our experience, the three most common causes of this error are:

  1. Incorrectly typed fields: When you create a new field in n8n, you need to specify its data type. If you forget to do this or set the wrong type, you'll get this error.
  2. String values in numeric fields: If you're trying to set a numeric field to a string value, n8n will throw an error. This is because the field is expecting a number, not a string.
  3. Boolean values in numeric fields: Similarly, if you're trying to set a numeric field to a boolean value, n8n will throw an error. This is because the field is expecting a number, not a boolean.

Step-by-step fix

To fix this error, follow these steps:

  1. Check the field type: Go to the Set node and check the field type for the field that's causing the error. Make sure it's set to the correct type (e.g., "number" or "boolean").
  2. Explicitly cast the value: If the field type is correct, try explicitly casting the value to the correct type. For example, if you're trying to set a numeric field to a string value, you can use the parseInt() function to cast the string to a number.
  3. Use a Code node: If you need to perform more complex data type conversions, consider using a Code node to perform the conversion. For example, you can use JavaScript to convert a string to a number or a boolean.

Here's an example of how you can use a Code node to explicitly cast a string value to a number:

// Set node: Field "age" is set to a string value "25"
// Code node:
const age = parseInt("25");
// Set node: Field "age" is now set to the number value 25
  1. Check the data source: If the error is still occurring, try checking the data source to see if the values are being received as strings instead of numbers. If so, you may need to perform additional data type conversions before setting the field.

Prevent it from coming back

To prevent this error from coming back, make sure to:

  1. Double-check the field type: Before setting a field, make sure its type is correct.
  2. Use explicit casting: When setting a field to a value that may not match the expected type, use explicit casting to convert the value to the correct type.
  3. Test thoroughly: Test your workflow thoroughly to make sure the error doesn't occur again.

  • Any relevant workflow settings or configurations
