Postgres API rate limit exceeded in n8n workflow

Error: rateLimiter: Rate limit exceeded · Node: Postgres

What this error actually means

The "rateLimiter: Rate limit exceeded" error in n8n is a clear indication that your workflow is attempting to make too many requests to your Postgres database within a certain time frame. This is a rate limiting mechanism built into the Postgres driver to prevent abuse and protect the database from being overwhelmed.

The three most common causes

Based on our experience, the three most common causes of this error are:

  1. Insufficient rate limiting configuration: If you're not configuring rate limiting correctly on the Postgres node, you may be exceeding the default rate limit.
  2. Highly concurrent workflows: If you have multiple workflows running concurrently, they may be competing for database connections and exceeding the rate limit.
  3. Infinite loops or stuck workflows: If a workflow is stuck in an infinite loop or not terminating properly, it can continue to make requests to the database, exceeding the rate limit.

Step-by-step fix

To fix the "rateLimiter: Rate limit exceeded" error, follow these steps:

  1. Check the Postgres node settings: Ensure that the Postgres node is configured to use a rate limiter. You can do this by navigating to the Postgres node, clicking on the "Settings" tab, and looking for the "Rate Limiter" section.
  2. Configure rate limiting: If you haven't already, configure rate limiting on the Postgres node. You can do this by setting a value for the "Rate Limit" field, which represents the maximum number of requests allowed within a certain time frame (e.g., 100 requests per minute).
  3. Add a delay: To prevent workflows from making too many requests too quickly, add a delay between requests using the "Wait" node. This will give the database time to process each request and prevent the rate limit from being exceeded.
  4. Implement retries: Configure retries on the Postgres node to handle cases where the rate limit is exceeded. You can do this by setting the "Max Tries" field to a value greater than 1 and the "Wait Between Tries (ms)" field to a value that allows the rate limit to reset.

Here's an example code block that you can use to add a delay between requests:

{
  "name": "Wait 10 seconds",
  "type": "Wait",
  "timeoutSeconds": 10
}

You can add this node to your workflow to introduce a delay between requests.

Prevent it from coming back

To prevent the "rateLimiter: Rate limit exceeded" error from coming back, make sure to:

  • Monitor your workflows for infinite loops or stuck workflows and terminate them as needed.
  • Regularly review and adjust your rate limiting configuration to ensure it's sufficient for your workflows.
  • Consider implementing additional error handling and logging to help identify and resolve issues quickly.

When to escalate

If you've tried the above steps and the error persists, it's likely that there's a more complex issue at play. In this case, consider escalating the issue to your n8n support team or a senior engineer for further assistance.
