n8n Google Sheets API limit error

Error: Rate Limit: Google Sheets API has exceeded the maximum allowed requests · Node: Google Sheets

What this error actually means

The "Rate Limit: Google Sheets API has exceeded the maximum allowed requests" error is a common issue that occurs when the Google Sheets API is hit with too many requests within a short period of time. This can happen when your workflow is designed to perform a large number of operations on Google Sheets, such as updating multiple rows or performing complex queries. The error message is a clear indication that your workflow is exceeding the rate limits set by the Google Sheets API.

The three most common causes

There are several reasons why your workflow may be hitting the rate limits on the Google Sheets API. Here are three common causes:

  • Insufficient retry configuration: If you're not configuring retries on the node, your workflow will continue to attempt the operation without waiting for the rate limit to reset.
  • Inadequate wait time between requests: If you're not waiting long enough between requests, you may be hitting the rate limit before it has a chance to reset.
  • Overly aggressive workflow design: If your workflow is designed to perform a large number of operations on Google Sheets in a short period of time, you may be hitting the rate limit even with proper retry and wait configuration.

Step-by-step fix

To fix this issue, you'll need to configure retries on the node and add a wait time between requests. Here's a step-by-step guide:

  1. Open the Google Sheets node and navigate to the Settings tab.
  2. Configure the "Retry On Fail" setting to "true".
  3. Set the "Max Tries" to a value that allows your workflow to wait for the rate limit to reset (e.g. 10-20 tries).
  4. Set the "Wait Between Tries (ms)" to a value that allows the rate limit to reset (e.g. 10,000-30,000ms).
  5. Create a new "Wait" node to add a delay between requests. Configure the "Duration" to a value that allows the rate limit to reset (e.g. 10-30 seconds).
  6. Use the "Error Trigger" to branch on an error and trigger the wait node.

Here's an example code block that you can use in a "Code" node to calculate the wait time between requests:

function calculateWaitTime() {
  const retryCount = 10; // adjust this value based on your workflow's needs
  const waitTime = 10000; // adjust this value based on your workflow's needs
  const waitTimeInSeconds = waitTime / 1000;
  const totalWaitTime = waitTimeInSeconds * retryCount;
  return totalWaitTime;
}

You can then use this function to set the wait time between requests in your workflow.

Prevent it from coming back

To prevent this issue from coming back, make sure to monitor your workflow's performance and adjust the retry and wait configuration as needed. You can also consider using a more robust retry strategy, such as exponential backoff, to reduce the likelihood of hitting the rate limit.

When to escalate

If you've followed the steps above and are still hitting the rate limit, it may be time to escalate the issue. This could involve:

  • Contacting the Google Sheets API support team to request an increase in the rate limit.
  • Reviewing your workflow design to identify areas for improvement.
  • Considering alternative APIs or services that have more generous rate limits.
  • Consulting with a n8n expert or developer to review your workflow configuration and provide guidance on how to improve performance.
