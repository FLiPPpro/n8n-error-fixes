n8n IF Node Condition Always False — Fix

Error: IF node always takes false branch · Node: IF

What this error actually means

The error message "IF node always takes false branch" indicates that the IF node in your n8n workflow is not behaving as expected. Specifically, it's always evaluating to false, even when it should be true. This error is often caused by a mismatch in the type or value of the data being compared in the IF node.

The three most common causes

After working with numerous n8n users, I've identified three common causes of this error:

  1. Type comparison mismatch: When comparing values of different types, n8n may not behave as expected. For example, comparing a string '0' to a number 0 will always result in false.
  2. Whitespace in values: Trailing or leading whitespace in values can cause the IF node to evaluate to false.
  3. Incorrect comparator: Using the wrong comparator (e.g., === instead of ==) can lead to unexpected results.

Step-by-step fix

To fix the "IF node always takes false branch" error, follow these steps:

  1. Check for type comparison mismatch: Ensure that the values being compared are of the same type. If you're comparing a string to a number, use the correct comparator (e.g., {{ "0" == 0 }}).
  2. Trim whitespace: Use the trim() function to remove any leading or trailing whitespace from the values being compared. You can use a Code node with the following JavaScript code:
{{ " 0" | trim() == 0 }}

This will remove any whitespace from the string '0' before comparing it to the number 0.

  1. Use the correct comparator: Double-check that you're using the correct comparator for the data types being compared. For example, use === for strict equality and == for loose equality.
  2. Verify the IF node configuration: Ensure that the IF node is configured correctly, including the correct branch and condition.

Prevent it from coming back

To prevent this error from occurring in the future, follow these best practices:

  1. Use the correct data types: Ensure that the data types being compared are consistent throughout the workflow.
  2. Trim whitespace: Always trim whitespace from values being compared.
  3. Use the correct comparator: Use the correct comparator for the data types being compared.
  4. Test thoroughly: Test your workflow thoroughly to ensure that the IF node is behaving as expected.

When to escalate

If you've followed the steps above and the error persists, it may be time to escalate the issue. This could involve:

  1. Checking the n8n logs: Review the n8n logs to see if there are any errors or warnings related to the IF node.
  2. Contacting the n8n support team: Reach out to the n8n support team for further assistance.
  3. Providing more context: Share more context about your workflow and the specific node causing the issue.

Remember to provide as much detail as possible when escalating the issue, including screenshots of your workflow and any relevant error messages.
