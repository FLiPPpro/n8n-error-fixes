Gmail API quota limit exceeded in n8n workflow

Error: quotaExceeded: Quota limit exceeded · Node: Gmail

What this error actually means

The quotaExceeded error in n8n's Gmail node means that you have exceeded the quota limit set by the Gmail API. This quota limit is the maximum number of requests you can make to the Gmail API within a certain time frame. When you exceed this limit, the Gmail API will return a quotaExceeded error, preventing you from sending emails.

The three most common causes

The quotaExceeded error can be caused by several factors. Here are the three most common causes:

  1. Sending too many emails at once: If you're sending a large number of emails simultaneously, you may exceed the quota limit. This can happen if you have a workflow that sends emails to a large number of recipients at the same time.
  2. Inadequate retry configuration: If you're not configuring retries properly, you may exceed the quota limit. This can happen if you're not setting a sufficient wait time between retries or if you're not setting a maximum number of retries.
  3. Gmail API quota limit: The Gmail API has a quota limit that is set by Google. If you exceed this limit, you'll receive a quotaExceeded error.

Step-by-step fix

To fix the quotaExceeded error, follow these steps:

  1. Check your workflow: Review your workflow to see if you're sending too many emails at once. Try to break up your workflow into smaller chunks, sending emails in batches of 10-20 at a time.
  2. Configure retries: Configure retries on the Gmail node by going to Settings → "Retry On Fail". Set a sufficient wait time between retries (e.g., 10-30 seconds) and a maximum number of retries (e.g., 5-10).
  3. Use the Wait node: Use the Wait node to add a delay between sending emails. This will help prevent you from exceeding the quota limit.
  4. Use a Code node to implement exponential backoff: Implement exponential backoff using a Code node. This will help prevent you from exceeding the quota limit by gradually increasing the wait time between retries.

To prevent the quotaExceeded error from coming back, follow these best practices:
