n8n Execution workflow failed to run

Error: Workflow failed · Node: Execute Workflow

What this error actually means

When you see the error message "Workflow failed" in n8n, it's often frustrating because it doesn't provide much context about what went wrong. However, this error is not as ominous as it seems. It simply means that the workflow execution reached a point where it encountered an error, and it stopped running.

In n8n, workflows are designed to be self-contained and fault-tolerant. When an error occurs, the workflow will typically stop executing and display the "Workflow failed" message. This is a deliberate design choice to prevent workflows from propagating errors and causing further issues.

The three most common causes

After analyzing numerous support requests, we've identified the three most common causes of the "Workflow failed" error:

  1. Missing or incorrect node configurations: This is often due to incorrect settings or missing configurations on specific nodes, such as API keys, database connections, or file paths.
  2. Invalid or malformed data: When workflows rely on data from external sources or previous node executions, incorrect or malformed data can cause errors and lead to workflow failures.
  3. Uncaught exceptions: In some cases, workflows may encounter unhandled exceptions or errors that are not properly caught and handled by the workflow.

Step-by-step fix

To troubleshoot and fix the "Workflow failed" error, follow these steps:

  1. Check node configurations: Review the node configurations for any errors or inconsistencies. Verify that API keys, database connections, and file paths are correct and up-to-date.
  2. Inspect data flow: Analyze the data flow between nodes and ensure that data is being passed correctly. Check for any invalid or malformed data that may be causing errors.
  3. Add error handling: To catch and handle errors, you can use the Continue On Fail setting on specific nodes or the Error Trigger (real workflow trigger). This will allow you to branch on errors and prevent the workflow from failing entirely.

Here's an example of how to use the Continue On Fail setting on an HTTP Request node:

{
  "name": "HTTP Request",
  "settings": {
    "retryOnFail": true,
    "maxTries": 3,
    "waitBetweenTriesMs": 5000,
    "continueOnFail": true
  },
  "parameters": {
    "url": "https://example.com/api/endpoint",
    "method": "GET",
    "headers": {
      "Authorization": "Bearer YOUR_API_KEY"
    }
  }
}

This configuration will retry the HTTP request up to 3 times with a 5-second delay between retries. If the request fails, the workflow will continue executing, allowing you to catch and handle the error.

Prevent it from coming back

To prevent the "Workflow failed" error from occurring in the future, make sure to:

  • Regularly review and update node configurations to ensure they are correct and up-to-date.
  • Validate and sanitize data before passing it between nodes.
  • Implement robust error handling mechanisms, such as using the Continue On Fail setting or the Error Trigger.

When to escalate

If you've tried the above steps and the "Workflow failed" error persists, it's likely that the issue is more complex and requires further investigation. In this case, it's best to:

  • Reach out to the n8n community or support forums for help.
  • Provide detailed logs and error messages to aid in troubleshooting.
  • Consider creating a minimal, reproducible example to demonstrate the issue.
