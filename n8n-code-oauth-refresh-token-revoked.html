Code node throws 'OAuth2 refresh token revoked' error

Error: OAuth2 refresh token revoked · Node: Code

What this error actually means

When you see the error message "OAuth2 refresh token revoked" in n8n, it means that the refresh token used by the OAuth2 node has been revoked by the OAuth2 provider. This can happen due to various reasons such as:

  • The user has revoked the authorization for your application.
  • The refresh token has expired.
  • The OAuth2 provider has revoked the token due to suspicious activity.

The three most common causes

Based on our experience, the three most common causes of this error are:

  1. User revocation: The user has manually revoked the authorization for your application, causing the refresh token to be revoked.
  2. Token expiration: The refresh token has expired, and the OAuth2 node is trying to use it to obtain a new access token.
  3. OAuth2 provider revocation: The OAuth2 provider has revoked the token due to suspicious activity or other reasons.

Step-by-step fix

To fix this error, you need to handle the situation where the refresh token is revoked. Here's a step-by-step guide:

  1. Check the OAuth2 node settings: Make sure that the OAuth2 node is configured correctly, including the client ID, client secret, and refresh token.
  2. Add retry logic: Configure the OAuth2 node to retry the request after a certain amount of time. You can do this by setting the "Retry On Fail" option to "true" and specifying the "Max Tries" and "Wait Between Tries (ms)" values.
  3. Use a Wait node: If the retry logic doesn't work, you can use a Wait node to introduce a delay before retrying the request. This will give the OAuth2 provider time to re-issue the refresh token.
  4. Handle the error: Use the "Continue On Fail" setting on the OAuth2 node to continue the workflow even if the request fails. You can then use a Code node to handle the error and decide what to do next.

Here's an example Code node that you can use to handle the error:

// Get the error message
const errorMessage = `OAuth2 refresh token revoked: ${error.message}`;

// Check if the error is due to the refresh token being revoked
if (error.message.includes("revoked")) {
  // If the refresh token is revoked, try to obtain a new one
  const newRefreshToken = await getNewRefreshToken();
  if (newRefreshToken) {
    // If a new refresh token is obtained, use it to retry the request
    const newAccessToken = await getAccessToken(newRefreshToken);
    if (newAccessToken) {
      // If a new access token is obtained, use it to retry the request
      const response = await retryRequest(newAccessToken);
      if (response) {
        // If the request is successful, continue with the workflow
        continue;
      } else {
        // If the request fails again, handle the error
        handleRequestError(response);
      }
    } else {
      // If no new access token is obtained, handle the error
      handleRequestError(null);
    }
  } else {
    // If no new refresh token is obtained, handle the error
    handleRequestError(null);
  }
} else {
  // If the error is not due to the refresh token being revoked, handle the error
  handleRequestError(error);
}

Note that this code assumes that you have functions getNewRefreshToken(), getAccessToken(), and retryRequest() that you need to implement to obtain a new refresh token and access token, and retry the request.

Prevent it from coming back

To prevent this error from coming back, you can:

  • Monitor your OAuth2 provider: Keep an eye on your OAuth2 provider's logs to detect any issues with the refresh token.
  • Implement token renewal: Implement a token renewal mechanism to obtain a new refresh token before it expires.
  • Use a more robust OAuth2 library: Consider using a more robust OAuth2 library that can handle errors and exceptions more robustly.
