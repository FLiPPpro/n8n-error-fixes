Gmail node throws 'OAuth2 refresh token revoked' error

Error: OAuth2 refresh token revoked · Node: Gmail

What this error actually means

When you see the error message "OAuth2 refresh token revoked" in n8n, it means that the refresh token used to authenticate your Gmail node has been revoked by Google. This can happen for a variety of reasons, including:

  • The token has expired and not been refreshed in time
  • The token has been intentionally revoked by the user or an administrator
  • The token has been compromised and is no longer trusted

Regardless of the reason, the error message indicates that the refresh token is no longer valid, and you'll need to take steps to obtain a new one.

The three most common causes

Based on our experience, the three most common causes of this error are:

  1. Token expiration: If the refresh token has expired and not been refreshed in time, you'll see this error. This can happen if the token has a short lifespan and is not being refreshed regularly.
  2. Token revocation: If the token has been intentionally revoked by the user or an administrator, you'll see this error. This can happen if the user has changed their password or if an administrator has revoked the token for security reasons.
  3. Token compromise: If the token has been compromised and is no longer trusted, you'll see this error. This can happen if the token has been leaked or stolen.

Step-by-step fix

To fix this error, follow these steps:

  1. Check the token expiration: If the token has expired, you'll need to obtain a new one. You can do this by:

  1. Configure the node to retry: To handle the case where the token has been revoked, you can configure the node to retry with a new token. To do this, go to the node's Settings tab and set the "Retry On Fail" option to "Yes". You can also set the "Max Tries" and "Wait Between Tries (ms)" options to control how many times the node will retry and how long it will wait between retries.
  1. Update the token: Once you have a new token, update the token in the node's settings. You can do this by going to the node's Settings tab and updating the "Refresh Token" field.

Prevent it from coming back

To prevent this error from coming back, you can take the following steps:

  1. Use a more robust token handling strategy: Instead of relying on a single refresh token, you can use a more robust token handling strategy that involves refreshing the token regularly or using a token refresh endpoint.
  2. Monitor the token expiration: You can monitor the token expiration and refresh the token before it expires.
  3. Implement token revocation handling: You can implement token revocation handling by checking the token revocation status before using the token.

When to escalate

If you've tried the steps above and are still seeing the error, it may be time to escalate the issue. This could involve:

  • Checking the Google API documentation to see if there are any known issues with the refresh token
  • Contacting the Google API support team for assistance
  • Reviewing your n8n workflow and configuration to ensure that everything is set up correctly
  • Seeking help from a n8n expert or the n8n community
