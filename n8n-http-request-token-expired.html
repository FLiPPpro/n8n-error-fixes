HTTP Request node throws 'invalid_grant: Token has been expired or revoked' error

Error: invalid_grant: Token has been expired or revoked · Node: HTTP Request

What this error actually means

The error message "invalid_grant: Token has been expired or revoked" indicates that the access token used for authentication with the HTTP Request node has expired or been revoked. This can happen due to various reasons, such as a short-lived token, a token refresh issue, or an invalid token.

The three most common causes

Based on our experience, the three most common causes of this error are:

  1. Expired access token: The access token used for authentication has expired, and the token refresh mechanism is not configured properly.
  2. Token refresh issue: The token refresh mechanism is not configured correctly, or the token refresh endpoint is not reachable.
  3. Invalid token: The access token used for authentication is invalid or has been revoked.

Step-by-step fix

To fix this issue, follow these steps:

  1. Check the token expiration time: Verify that the access token used for authentication has not expired. You can do this by checking the token's expiration time in the token response.
  2. Configure token refresh: If the token has expired, configure the token refresh mechanism to refresh the token before it expires. You can do this by setting the Refresh Token option to true in the HTTP Request node's Settings tab.
  3. Use a longer-lived token: Consider using a longer-lived token to reduce the frequency of token refreshes.
  4. Implement token refresh retry: To implement token refresh retry, you can use the Wait node to introduce a delay between token refresh attempts. Here's an example code block that you can use in a Code node:
const tokenRefreshInterval = 5000; // 5 seconds
const maxTokenRefreshAttempts = 3;

// Token refresh retry logic
function tokenRefreshRetry(attempts) {
  if (attempts >= maxTokenRefreshAttempts) {
    // Token refresh failed, throw an error
    throw new Error('Token refresh failed');
  }
  // Wait for the token refresh interval before retrying
  const delay = tokenRefreshInterval * attempts;
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      resolve();
    }, delay);
  });
}

// Call the token refresh retry function
tokenRefreshRetry(0)
  .then(() => {
    // Refresh the token
    const tokenRefreshEndpoint = 'https://your-token-refresh-endpoint.com';
    const token = await fetch(tokenRefreshEndpoint, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({
        grant_type: 'refresh_token',
        refresh_token: 'your-refresh-token',
      }),
    });
    const newToken = await token.json();
    // Use the new token for authentication
  })
  .catch((error) => {
    // Handle token refresh error
  });
  1. Implement error handling: To handle the case where the token refresh fails, you can use the Error Trigger to trigger an error in the workflow. Alternatively, you can use the Continue On Fail setting on the HTTP Request node to continue the workflow even if the token refresh fails.

Prevent it from coming back

To prevent this issue from coming back, consider the following:

  • Monitor token expiration: Regularly monitor the token expiration time to ensure that the token does not expire before it is refreshed.
  • Implement token refresh monitoring: Implement monitoring for token refresh attempts to detect any issues with the token refresh mechanism.
  • Use a longer-lived token: Consider using a longer-lived token to reduce the frequency of token refreshes.

When to escalate

Escalate this issue to your team or support channel if:

  • You are unsure about how to configure the token refresh mechanism.
  • You are experiencing frequent token refresh failures.
  • You are unable to implement token refresh retry logic.
  • You are experiencing issues with token expiration or invalid tokens.
