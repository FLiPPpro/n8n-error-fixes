Postgres node reports unique constraint violation in n8n

Error: ERROR: duplicate key value violates unique constraint · Node: Postgres

What this error actually means

The error message "ERROR: duplicate key value violates unique constraint" is a common issue when working with Postgres databases in n8n. This error occurs when you're trying to insert data into a table that has a unique constraint, and the value you're trying to insert already exists in that column.

In Postgres, a unique constraint is a rule that ensures each value in a column is unique. When you try to insert a value that already exists in that column, the database throws an error, preventing the insertion.

The three most common causes

Based on our experience, there are three common causes of this error:

  1. Duplicate data in the database: This is the most common cause of this error. If you're trying to insert data that already exists in the database, the unique constraint will prevent the insertion.
  2. Incorrect data type: If the data type of the column is not correctly set, it can cause this error. For example, if you're trying to insert a string into a column that's set to be an integer, the database will throw an error.
  3. Missing or incorrect indexes: If the indexes on the table are not correctly set, it can cause this error. Indexes are used to speed up queries, but they can also prevent duplicate values from being inserted.

Step-by-step fix

To fix this error, follow these steps:

  1. Check the database for duplicate data: Before trying to insert new data, check the database to see if the value already exists. You can do this by running a SQL query to check for duplicates.
SELECT * FROM your_table WHERE your_column = 'value_to_check';
  1. Update the data type: If the data type of the column is incorrect, update it to the correct type. For example, if you're trying to insert a string into a column that's set to be an integer, update the column type to string.
  2. Create or update indexes: If the indexes on the table are not correctly set, create or update them to prevent duplicate values from being inserted.
CREATE INDEX your_index_name ON your_table (your_column);
  1. Configure the HTTP Request node: In n8n, configure the HTTP Request node to retry the request if it fails due to a duplicate key error. You can do this by setting the "Retry On Fail" option to "true" and setting the "Max Tries" option to a value greater than 1.
  2. Use the "Wait" node: If the issue persists, use the "Wait" node to add a delay between retries. This can help prevent the database from becoming overwhelmed with requests.

Prevent it from coming back

To prevent this error from coming back, follow these best practices:

  1. Use unique IDs: Use unique IDs for each record in the database. This will prevent duplicate values from being inserted.
  2. Use transactions: Use transactions to ensure that either all or none of the changes are committed to the database. This will prevent partial inserts from being committed.
  3. Monitor the database: Monitor the database for duplicate values and correct them before they cause issues.
