Cron Node Error - Invalid Schedule

Error: Cron schedule is invalid · Node: Cron

What this error actually means

The "Cron schedule is invalid" error in n8n's Cron node indicates that the schedule you've set for the node is not correctly formatted or is not valid for the node to execute. This error can occur due to various reasons, including incorrect syntax, invalid time zones, or conflicts with existing schedules.

The three most common causes

Based on our experience, the three most common causes of this error are:

  1. Incorrect syntax: Make sure you've entered the schedule in the correct format. The Cron node uses the standard Cron syntax, which consists of five fields: minute, hour, day of month, month, and day of week. Each field is separated by a space, and the fields are specified in the following order: minute, hour, day of month, month, and day of week.
  2. Invalid time zones: Ensure that the time zone you've specified is valid and correctly formatted. The Cron node uses the TZ environment variable to determine the time zone. If you're using a time zone that's not in the list of supported time zones, you may encounter this error.
  3. Conflicts with existing schedules: If you have multiple Cron nodes with overlapping schedules, you may encounter this error. Make sure that each schedule is unique and doesn't conflict with existing schedules.

Step-by-step fix

To fix this error, follow these steps:

  1. Check the schedule syntax: Double-check that your schedule is correctly formatted and free of syntax errors. You can use online Cron syntax validators to help you identify any issues.
  2. Verify the time zone: Ensure that the time zone you've specified is valid and correctly formatted. You can use the TZ environment variable to specify the time zone.
  3. Check for conflicts: Review your workflow and ensure that each Cron node has a unique schedule that doesn't conflict with existing schedules.
  4. Use a Code node to validate the schedule: If you're still unsure about the schedule syntax or time zone, you can use a Code node to validate the schedule programmatically. Here's an example JavaScript code block that you can use in a Code node to validate the schedule:
const schedule = '0 0 * * *'; // Replace with your schedule
const cron = require('cron');
const job = new cron.CronJob(schedule, () => {
  console.log('Schedule is valid');
}, null, true, 'America/New_York'); // Replace with your time zone
if (job.cron.schedule(schedule)) {
  console.log('Schedule is valid');
} else {
  console.log('Schedule is invalid');
}
  1. Update the Cron node: Once you've validated the schedule, update the Cron node with the corrected schedule.

Prevent it from coming back

To prevent this error from occurring in the future, make sure to:

  • Double-check the schedule syntax and time zone before setting up a new Cron node.
  • Use a Code node to validate the schedule programmatically.
  • Review your workflow regularly to ensure that each Cron node has a unique schedule that doesn't conflict with existing schedules.

When to escalate

If you've tried the above steps and still encounter the "Cron schedule is invalid" error, it's likely due to a more complex issue that requires further investigation. In this case, please:

  • Provide detailed logs and screenshots of the error.
  • Share your workflow and Cron node configuration.
  • Specify the exact error message and any relevant error codes.
  • Describe any changes you've made to the workflow or Cron node configuration recently.

This will help us to better understand the issue and provide a more accurate solution.
