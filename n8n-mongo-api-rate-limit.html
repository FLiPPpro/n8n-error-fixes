MongoDB API rate limit exceeded in n8n workflow

Error: rateLimiter: Rate limit exceeded · Node: MongoDB

What this error actually means

When you see the rateLimiter: Rate limit exceeded error message in n8n, it means that the MongoDB node has hit its rate limit for a specific time window. This can happen when you're making too many requests to MongoDB within a short period, causing the MongoDB rate limiter to block your requests.

The three most common causes

There are three common causes for this error:

  1. Insufficient rate limiting configuration: If you haven't configured the rate limiter on the MongoDB node, or if the configuration is too low, you may exceed the rate limit.
  2. High-volume data processing: If you're processing a large volume of data, you may be making too many requests to MongoDB, causing the rate limiter to block your requests.
  3. Misconfigured retry settings: If you've configured the retry settings on the node to retry failed requests too aggressively, you may be exceeding the rate limit.

Step-by-step fix

To fix this issue, follow these steps:

  1. Check the rate limiter configuration: Go to the MongoDB node's Settings tab and check the rate limiter configuration. If it's not configured, set it to a reasonable value (e.g., 100 requests per minute).
  2. Adjust the retry settings: Go to the MongoDB node's Settings tab and adjust the retry settings to reduce the number of retries or increase the wait time between retries.
  3. Implement a delay between requests: Use the "Wait" node to introduce a delay between requests to MongoDB. This will help spread out the requests and avoid exceeding the rate limit.

Here's an example code block that you can use in a "Code" node to introduce a delay between requests:

const delay = 5000; // 5 seconds
return new Promise(resolve => setTimeout(resolve, delay));

You can paste this code into a "Code" node and set it to run before the MongoDB node. This will introduce a 5-second delay between requests.

Prevent it from coming back

To prevent this issue from coming back, follow these best practices:

  • Monitor your rate limiter configuration: Regularly check your rate limiter configuration to ensure it's set to a reasonable value.
  • Implement rate limiting on the client-side: Consider implementing rate limiting on the client-side (e.g., using a library like rate-limiter-flexible) to prevent excessive requests from being made.
  • Optimize your workflow: Optimize your workflow to reduce the number of requests made to MongoDB.

When to escalate

If you've tried the above steps and the issue persists, it's likely due to a more complex issue, such as:

  • MongoDB rate limiter configuration: If you're using a custom rate limiter configuration on MongoDB, it may be causing the issue.
  • High-volume data processing: If you're processing a large volume of data, you may need to scale your MongoDB instance or adjust your workflow to reduce the number of requests.
  • Misconfigured retry settings: If you've configured the retry settings on the node to retry failed requests too aggressively, you may need to adjust the settings.

In this case, it's recommended to escalate the issue to a senior engineer or MongoDB expert for further assistance.
