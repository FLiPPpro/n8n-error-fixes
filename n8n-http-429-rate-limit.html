HTTP Request node 429 Too Many Requests error

Error: 429 Too Many Requests · Node: HTTP Request

What this error actually means

The 429 Too Many Requests error is a common issue that occurs when your workflow is sending too many HTTP requests in a short time. This can happen when your workflow is designed to fetch data from an external API, and the API has rate limits in place to prevent abuse.

In this case, the API is intentionally blocking your workflow's requests because it believes you're sending too many requests too quickly. This can be frustrating, especially if you're not aware of the rate limits in place.

The three most common causes

Based on our experience, the three most common causes of the 429 Too Many Requests error in n8n are:

  1. Insufficient retry configuration: If you're not configuring retries correctly on the HTTP Request node, your workflow may be sending too many requests in a short time, triggering the API's rate limits.
  2. Inadequate delay between requests: If you're not adding a sufficient delay between requests using the Wait node, your workflow may be sending too many requests too quickly, triggering the API's rate limits.
  3. Lack of error handling: If you're not configuring your workflow to handle errors properly, you may not be aware of the rate limits in place, leading to repeated attempts to send requests and triggering the API's rate limits.

Step-by-step fix

To fix the 429 Too Many Requests error, follow these steps:

  1. Check your retry configuration: Go to the HTTP Request node and check the "Retry On Fail", "Max Tries", and "Wait Between Tries (ms)" settings. Make sure you have sufficient retries configured and a reasonable wait time between retries.
  2. Add a delay between requests: Insert a Wait node after the HTTP Request node to add a delay between requests. You can configure the delay to be a fixed value (e.g., 1 second) or a dynamic value based on the response from the API (e.g., wait for 1 second for each 10 requests).
  3. Handle errors properly: Use the Error Trigger to branch on errors and handle them properly. You can also use the "Continue On Fail" setting on the HTTP Request node to continue executing the workflow even if the request fails.

Here's an example code block that you can use to add a delay between requests based on the response from the API:

{
  "nodes": [
    {
      "name": "HTTP Request",
      "type": "http-request",
      "settings": {
        "retryOnFail": true,
        "maxTries": 3,
        "waitBetweenTries": 1000
      },
      "parameter": {
        "url": "https://api.example.com/data",
        "method": "GET",
        "headers": {
          "Authorization": "Bearer YOUR_API_KEY"
        }
      }
    },
    {
      "name": "Wait",
      "type": "wait",
      "settings": {
        "waitTime": "{{ $node[\"HTTP Request\"].response.headers['Retry-After'] || 1000 }}"
      }
    }
  ]
}

In this example, the Wait node is configured to wait for the value of Retry-After header in the response from the API. If the header is not present, the Wait node will wait for 1 second.

Prevent it from coming back

To prevent the 429 Too Many Requests error from coming back, make sure to:

  • Monitor your workflow's performance and adjust the retry configuration and delay between requests accordingly.
  • Keep an eye on the API's rate limits and adjust your workflow's request frequency accordingly.
  • Use the Error Trigger to branch on errors and handle them properly.

When to escalate

If you've tried the above steps and the 429 Too Many Requests error persists, it's likely that there's an underlying issue with your workflow or the API that's causing the problem. In this case, it's time to escalate the issue to your team or the API provider for further assistance. Make sure to provide as much detail as possible about the error, including the workflow configuration, API response, and any relevant logs.
