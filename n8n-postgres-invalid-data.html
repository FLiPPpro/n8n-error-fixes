n8n Postgres node returns 'invalid input syntax for integer'

Error: ERROR: invalid input syntax for integer · Node: Postgres

What this error actually means

The ERROR: invalid input syntax for integer message is a common Postgres error that occurs when n8n tries to execute a query with invalid data. Specifically, it happens when the Postgres node expects an integer value but receives something that can't be converted to an integer.

This error can be caused by various factors, including:

  • A mismatch between the data type of a field in your database and the data type expected by the Postgres node.
  • Invalid or malformed data being passed to the Postgres node.
  • A query that is trying to insert or update a value that doesn't match the expected data type.

The three most common causes

Based on our experience and support requests, the three most common causes of this error are:

  1. Data type mismatch: When the data type of a field in your database doesn't match the data type expected by the Postgres node.
  2. Invalid or malformed data: When the data being passed to the Postgres node is invalid or malformed, causing the query to fail.
  3. Query issues: When the query itself is trying to insert or update a value that doesn't match the expected data type.

Step-by-step fix

To fix this error, follow these steps:

  1. Check the data type: Verify that the data type of the field in your database matches the data type expected by the Postgres node. You can do this by checking the database schema or by running a query to check the data type of the field.
  2. Check the query: Review the query being executed by the Postgres node to ensure it's not trying to insert or update a value that doesn't match the expected data type.
  3. Use a Wait node: Add a Wait node to introduce a delay between retries. This can help prevent the Postgres node from being overwhelmed and improve the chances of successful execution.

Here's an example of how you can use a Wait node to introduce a delay between retries:

{
  "name": "Wait",
  "type": "wait",
  "settings": {
    "waitTime": "10s"
  }
}

This will introduce a 10-second delay between retries.

  1. Configure the Postgres node: Make sure the Postgres node is configured to retry on failure. You can do this by going to the Postgres node's Settings tab and enabling the "Retry On Fail" option.

Prevent it from coming back

To prevent this error from coming back, make sure to:

  • Validate your data: Ensure that the data being passed to the Postgres node is valid and well-formed.
  • Use the correct data type: Verify that the data type of the field in your database matches the data type expected by the Postgres node.
  • Test your queries: Review your queries to ensure they're not trying to insert or update a value that doesn't match the expected data type.

When to escalate

If you've tried the above steps and the error persists, it's likely a more complex issue that requires further investigation. In this case, you should:

  • Review your database schema and query logs to identify any potential issues.
  • Reach out to the n8n community or support team for further assistance.
  • Consider consulting with a database expert or a n8n specialist to help resolve the issue.
