n8n Code node type error message

Error: value is not of expected type · Node: Code

What this error actually means

When you encounter the "value is not of expected type" error in n8n, it means that the Code node is trying to perform an operation on a value that doesn't match the expected data type. This can happen when you're trying to manipulate data in a way that doesn't account for its actual type.

For example, if you're trying to concatenate a string with a number, n8n will throw this error because it expects the second operand to be a string, not a number.

The three most common causes

Here are the most common reasons why this error occurs:

  1. Incorrect data type: As mentioned earlier, this error occurs when you're trying to perform an operation on a value with the wrong data type.
  2. Missing type coercion: n8n doesn't automatically coerce data types, so if you're trying to perform an operation that requires a specific type, you need to explicitly convert the value.
  3. Invalid expression: If you're using an expression to manipulate data, make sure it's correct and doesn't contain any syntax errors.

Step-by-step fix

To fix this error, follow these steps:

  1. Check the data type: Verify that the data type of the value you're trying to manipulate matches the expected type.
  2. Use type coercion: If you need to convert a value to a specific type, use the typeof operator or the parseInt/parseFloat functions.
  3. Correct the expression: If you're using an expression, make sure it's correct and doesn't contain any syntax errors.

Here's an example code block that demonstrates how to use type coercion:

// Assuming you have a string variable called "name" and you want to convert it to an integer
let age = parseInt(name);

In this example, we're using the parseInt function to convert the string value of name to an integer. If the string can't be converted to an integer, parseInt will return NaN (Not a Number).

Prevent it from coming back

To prevent this error from occurring in the future, follow these best practices:

  1. Validate data types: Always verify the data type of the values you're working with.
  2. Use type coercion: Use type coercion functions like parseInt or parseFloat to convert values to the correct type.
  3. Test your expressions: Thoroughly test your expressions to ensure they're correct and don't contain any syntax errors.

When to escalate

If you've tried the above steps and the error persists, it may be time to escalate the issue. Here are some scenarios where you should consider escalating:

  • You're not sure what's causing the error or how to fix it.
  • You've tried all the above steps and the error still occurs.
  • You're experiencing frequent errors that are impacting your workflow.

In this case, it's best to reach out to the n8n community or support team for further assistance.
