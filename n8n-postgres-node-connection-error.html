Postgres node in n8n connection issue with SSL certificate

Error: Error establishing connection: SSL certificate issue · Node: Postgres

What this error actually means

The error "Error establishing connection: SSL certificate issue" in n8n indicates that there's a problem with the SSL encryption when connecting to your Postgres database. This can happen for a few reasons, but the underlying issue is usually related to the SSL certificate configuration.

The three most common causes

  1. Incompatible SSL certificate: Make sure the SSL certificate used by your Postgres database is compatible with the one used by n8n. This includes the certificate type (e.g., PEM, DER), the encryption algorithm, and the key size.
  2. Incorrect SSL certificate path: Ensure that the path to the SSL certificate file is correct in the n8n configuration. Double-check the file path, file name, and extension.
  3. Missing or incorrect trust store: If your Postgres database uses a self-signed certificate or a certificate from a custom Certificate Authority (CA), you might need to add the certificate or the CA's root certificate to the trust store.

Step-by-step fix

To resolve the issue, follow these steps:

  1. Verify the SSL certificate: Check the SSL certificate used by your Postgres database to ensure it's correct and compatible with n8n. You can do this by connecting to your Postgres database using a tool like psql or a GUI client like pgAdmin.
  2. Configure the SSL certificate path: In the n8n workflow, navigate to the Postgres node's Settings tab and ensure the SSL certificate path is correct. If you're using a custom certificate, provide the path to the certificate file (e.g., /path/to/ssl/cert.pem).
  3. Add the trust store: If your Postgres database uses a self-signed certificate or a custom CA, you need to add the certificate or the CA's root certificate to the trust store. You can do this by creating a new file (e.g., truststore.pem) containing the certificate or the CA's root certificate. Then, provide the path to this file in the Postgres node's Settings tab.

Here's an example code block to add the trust store to the Postgres node's configuration:

{
  "name": "Postgres Node",
  "settings": {
    "ssl": {
      "cert": "/path/to/ssl/cert.pem",
      "key": "/path/to/ssl/key.pem",
      "ca": "/path/to/truststore.pem"
    }
  }
}

In this example, replace /path/to/ssl/cert.pem and /path/to/ssl/key.pem with the actual paths to your SSL certificate and key files. For the trust store, provide the path to the file containing the certificate or the CA's root certificate (e.g., /path/to/truststore.pem).

  1. Test the connection: After configuring the SSL certificate path and trust store, test the connection to your Postgres database by running the workflow. If the connection is successful, you should see the data in the n8n workflow.

Prevent it from coming back

To prevent this issue from recurring, make sure to:

  • Regularly update your SSL certificate and key files to ensure they're compatible with n8n.
  • Keep the trust store up-to-date by adding new certificates or CA's root certificates as needed.
  • Monitor your n8n workflow logs for any SSL-related errors or warnings.

When to escalate

If you've tried the above steps and still encounter the "Error establishing connection: SSL certificate issue" error, it's likely that the issue is more complex and requires further investigation. In this case, consider escalating the issue to your n8n support team or a PostgreSQL expert for further assistance.
