n8n Webhook Test URL vs Production URL — Why Only One Works

Error: webhook works in editor but not in production · Node: Webhook

What this error actually means

The error "webhook works in editor but not in production" can be misleading. It's not a straightforward issue with the webhook itself, but rather a configuration or setup problem that prevents the webhook from triggering correctly in production. This error typically occurs when the user is expecting the webhook to trigger automatically when a new workflow is created or updated, but it only works when the "Execute Workflow" button is clicked in the editor.

The three most common causes

There are three common causes for this issue:

  1. Incorrect workflow status: In production, the workflow is not active, so the webhook is not triggered. This is because the webhook only works when the workflow is active.
  2. Missing or incorrect webhook URL: The webhook URL is not set up correctly in the production environment, or it's not properly configured in the workflow.
  3. Insufficient permissions: The user running the workflow does not have the necessary permissions to trigger the webhook.

Step-by-step fix

To fix this issue, follow these steps:

  1. Check workflow status: Make sure the workflow is active in production. If it's not, activate it and try triggering the webhook again.
  2. Verify webhook URL: Check that the webhook URL is correctly set up in the production environment. You can do this by looking at the workflow's settings and ensuring that the webhook URL is properly configured.
  3. Configure webhook retry options: Go to the HTTP Request node's Settings tab and configure the retry options. Set "Retry On Fail" to true, "Max Tries" to a reasonable number (e.g., 3), and "Wait Between Tries (ms)" to a suitable delay (e.g., 5000).
  4. Use a "Wait" node: Add a "Wait" node to the workflow to introduce a delay between retries. This will give the webhook time to trigger successfully.
  5. Use an "Error Trigger": Configure an "Error Trigger" to branch on an error. This will allow the workflow to continue running even if the webhook fails to trigger.

Here's an example code block you can use in a "Code" node to implement the retry logic:

{
  "name": "Retry Webhook",
  "parameters": {
    "retryOnFail": true,
    "maxTries": 3,
    "waitBetweenTries": 5000
  }
}

This code sets up the retry options for the HTTP Request node. You can adjust the values as needed.

Prevent it from coming back

To prevent this issue from coming back, make sure to:

  • Regularly review and update the workflow's settings, including the webhook URL and retry options.
  • Monitor the workflow's logs for any errors or issues that may indicate a problem with the webhook.
  • Test the webhook regularly to ensure it's working correctly.

When to escalate

If you've tried the above steps and the issue persists, it may be time to escalate the problem to a senior engineer or the n8n support team. Be prepared to provide detailed information about the issue, including:

  • The exact error message and any relevant logs.
  • The workflow's settings and configuration.
  • Any changes made to the workflow or environment recently.
  • Any relevant code or configuration files.
