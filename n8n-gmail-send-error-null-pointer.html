Gmail Send Email Node Error: TypeError: Cannot read properties of null

Error: TypeError: Cannot read properties of null (reading 'X') · Node: Gmail

What this error actually means

The error message TypeError: Cannot read properties of null (reading 'X') indicates that the n8n workflow is trying to access a property of an object that is null. In this case, the property in question is X, which is likely a recipient's email address. This error occurs when the recipient field is empty or null, causing the workflow to fail.

The three most common causes

Based on our experience, the three most common causes of this error are:

  1. Missing or empty recipient field: The recipient field is not populated, or it is empty, causing the workflow to fail.
  2. Recipient field is null: The recipient field is explicitly set to null, causing the workflow to fail.
  3. Incorrect data type: The recipient field is not set to the correct data type (e.g., string, email), causing the workflow to fail.

Step-by-step fix

To fix this error, follow these steps:

  1. Check the recipient field: Verify that the recipient field is populated and not empty. If it is empty, update the field with the correct recipient email address.
  2. Configure the Gmail node: Open the Gmail node's Settings tab and ensure that the "Retry On Fail" option is enabled. Set the "Max Tries" to a reasonable value (e.g., 3) and the "Wait Between Tries (ms)" to a suitable delay (e.g., 5000).
  3. Add a conditional statement: Create a new Code node and add the following JavaScript code:
if (item.recipient === null || item.recipient === "") {
  return [{ error: "Recipient field is empty" }];
}

This code checks if the recipient field is null or empty. If it is, the workflow will fail and display an error message.

  1. Add a Wait node: After the Code node, add a Wait node to introduce a delay between retries. Set the delay to a suitable value (e.g., 5000 ms).
  2. Configure the HTTP Request node: Open the HTTP Request node's Settings tab and ensure that the "Retry On Fail" option is enabled. Set the "Max Tries" to a reasonable value (e.g., 3) and the "Wait Between Tries (ms)" to a suitable delay (e.g., 5000).

Prevent it from coming back

To prevent this error from occurring in the future, follow these best practices:

  1. Validate recipient field: Ensure that the recipient field is validated and sanitized before sending the email.
  2. Use a default recipient: Set a default recipient email address to prevent the workflow from failing if the recipient field is empty.
  3. Monitor workflow logs: Regularly monitor the workflow logs to catch any errors or issues before they become critical.

When to escalate

If you have followed the steps above and the error persists, it may be necessary to escalate the issue to the n8n support team. Before doing so, ensure that you have:

  1. Verified the recipient field: Double-check that the recipient field is populated and not empty.
  2. Configured the nodes correctly: Ensure that the Gmail node and HTTP Request node are configured correctly, including the retry options.
  3. Checked the workflow logs: Review the workflow logs to identify any errors or issues that may be causing the problem.

If you are still experiencing issues, please provide the workflow logs and any relevant configuration details to the n8n support team for further assistance.
