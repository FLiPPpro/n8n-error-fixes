Webhook Node Invalid Signature Error in n8n Workflow

Error: Invalid signature · Node: Webhook

What this error actually means

When you see the "Invalid signature" error in n8n, it means that the Webhook node is unable to verify the signature of the incoming request. This is a security feature designed to prevent tampering with the request data. The signature is generated by n8n and sent back to the client, which must include it in the subsequent request. If the signature doesn't match, the request is rejected.

The three most common causes

After analyzing many cases of this error, we've identified three common causes:

  1. Incorrect signature secret: Make sure you've set the correct signature secret in the Webhook node's Settings tab. This secret is used to generate the signature, and if it's not set correctly, the signature will be invalid.
  2. Missing or incorrect signature header: Ensure that the signature header is included in the request and is correctly formatted. The header should be named X-n8n-Signature and contain the signature value.
  3. Signature expiration: If you're using a signature expiration time, make sure it's set correctly. If the signature expires before the request is made, it will be invalid.

Step-by-step fix

To fix the "Invalid signature" error, follow these steps:

  1. Check the signature secret: Go to the Webhook node's Settings tab and verify that the signature secret is correctly set. If it's not set, enter a secret of your choice and save the changes.
  2. Check the signature header: In the request that's being sent to the Webhook node, ensure that the X-n8n-Signature header is included and contains the correct signature value. You can do this by adding a Wait node with a Code node inside to print the request headers.
console.log(req.headers);

This will print the request headers, including the X-n8n-Signature header. If it's not included, add it to the request.

  1. Check signature expiration: If you're using a signature expiration time, ensure that it's set correctly. If the signature expires before the request is made, it will be invalid.

Here's an example of how to set the signature secret and signature header correctly:

{
  "name": "Webhook",
  "settings": {
    "signatureSecret": "my_secret_key",
    "signatureExpiration": 3600 // 1 hour
  },
  "parameters": {
    "url": "https://example.com/webhook",
    "method": "POST",
    "headers": {
      "X-n8n-Signature": "{{=signature}}"
    }
  }
}

In this example, we've set the signature secret to my_secret_key and the signature expiration to 1 hour. We've also included the X-n8n-Signature header in the request with the correct signature value.

Prevent it from coming back

To prevent the "Invalid signature" error from coming back, make sure to:

  • Regularly check the signature secret and update it if necessary.
  • Ensure that the signature header is included in all requests to the Webhook node.
  • Monitor the signature expiration time and adjust it as needed.

When to escalate

If you've followed the steps above and the "Invalid signature" error persists, it may be worth escalating the issue to the n8n support team. Provide them with the following information:

  • The n8n version you're using
  • The exact error message
  • The Webhook node configuration
  • Any relevant request headers or body data

This will help the support team to investigate the issue further and provide a solution.
