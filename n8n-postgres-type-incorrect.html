n8n Postgres node type incorrect error message

Error: value is not of expected type · Node: Postgres

What this error actually means

The "value is not of expected type" error in n8n's Postgres node is a common issue that occurs when the data type of the value being inserted or updated does not match the expected data type of the target field in the database. This error can be frustrating, especially when you're not sure where to start troubleshooting.

The three most common causes

After analyzing numerous reports of this error, we've identified the following three most common causes:

  1. Incorrect data type: The most common cause of this error is when the data type of the value being inserted or updated does not match the expected data type of the target field in the database. For example, if you're trying to insert a string value into a field that's defined as an integer, you'll get this error.
  2. Database schema mismatch: Another common cause of this error is when the database schema has changed, but the n8n workflow hasn't been updated to reflect the changes. This can happen when you add or remove fields from a table, or when you change the data type of a field.
  3. Invalid JSON data: If you're using the Postgres node to insert or update JSON data, this error can occur if the JSON data is not properly formatted or if it contains invalid characters.

Step-by-step fix

To fix the "value is not of expected type" error, follow these steps:

  1. Check the database schema: Verify that the database schema matches the expected data type of the target field. You can do this by running a DESCRIBE query on the table and field in question.
  2. Check the data type of the value: Verify that the data type of the value being inserted or updated matches the expected data type of the target field. You can do this by using the typeof operator in a Code node to check the data type of the value.
  3. Use a Code node to validate the data: Write a Code node that uses JavaScript to validate the data before it's inserted or updated. For example, you can use the following code to check if a value is a string:
const value = {{value}};
if (typeof value !== 'string') {
  return { error: 'Value is not a string' };
}
  1. Use a Wait node to add a delay: If the issue is caused by a database schema mismatch or invalid JSON data, you can use a Wait node to add a delay between attempts to insert or update the data. This can give the database time to update the schema or validate the JSON data.
  2. Configure the Postgres node to retry: Configure the Postgres node to retry the operation if it fails. You can do this by setting the "Retry On Fail" option to "true" and configuring the "Max Tries" and "Wait Between Tries (ms)" options.

Prevent it from coming back

To prevent the "value is not of expected type" error from coming back, follow these best practices:

  • Regularly update your n8n workflow: Make sure to regularly update your n8n workflow to reflect changes to the database schema.
  • Use a Code node to validate data: Use a Code node to validate data before it's inserted or updated.
  • Configure the Postgres node to retry: Configure the Postgres node to retry the operation if it fails.

When to escalate

If you've tried the above steps and the error persists, it may be time to escalate the issue. This could involve:

  • Checking the database logs: Check the database logs to see if there are any errors or warnings related to the issue.
