MongoDB node in n8n connection lost error on restart

Error: Connection lost: Unable to reconnect · Node: MongoDB

What this error actually means

When you see the "Connection lost: Unable to reconnect" error in n8n, it means that the integration with your MongoDB database has lost its connection. This can happen due to various reasons such as network issues, database downtime, or incorrect configuration. The error message is clear, but the underlying cause might not be immediately apparent. In this article, we'll explore the common causes of this error and provide a step-by-step guide to fix it.

The three most common causes

  1. Network issues: This is the most common cause of connection loss. If your MongoDB instance is not reachable from the n8n server, you'll see this error.
  2. Database downtime: If your MongoDB database is down for maintenance or has encountered an issue, n8n will not be able to connect.
  3. Incorrect configuration: Misconfigured MongoDB credentials or connection settings can cause the connection to fail.

Step-by-step fix

To fix the "Connection lost: Unable to reconnect" error, follow these steps:

  1. Check the MongoDB credentials: Ensure that the MongoDB credentials (username, password, and host) are correct and up-to-date. You can do this by checking the Settings tab of the MongoDB node.
  2. Verify the connection settings: Double-check the connection settings, such as the database name, collection name, and port number. Make sure they match the actual MongoDB configuration.
  3. Check the MongoDB instance: Verify that the MongoDB instance is running and accessible from the n8n server. You can use a tool like mongo or a MongoDB client to check the instance's status.
  4. Add retries to the MongoDB node: Configure the MongoDB node to retry the connection. You can do this by setting the Retry On Fail option to true and adjusting the Max Tries and Wait Between Tries (ms) settings to your desired values.

Here's an example code block that you can paste into a Code node to add retries to the MongoDB node:

{
  "name": "MongoDB",
  "settings": {
    "retryOnFail": true,
    "maxTries": 3,
    "waitBetweenTries": 5000
  }
}

This code sets the retryOnFail option to true, allowing the node to retry the connection. It also sets the maxTries option to 3, which means the node will retry the connection up to 3 times. The waitBetweenTries option is set to 5000ms, which means the node will wait 5 seconds between retries.

  1. Test the connection: After making these changes, test the connection by running a workflow or a single operation. If the connection is successful, you should see the data being processed or inserted into the MongoDB database.

Prevent it from coming back

To prevent the "Connection lost: Unable to reconnect" error from coming back, make sure to:

  • Regularly check the MongoDB credentials and connection settings for any changes or updates.
  • Monitor the MongoDB instance for any issues or downtime.
  • Adjust the retry settings on the MongoDB node to suit your specific needs.

When to escalate

If you've tried the above steps and the error persists, it's likely that there's a more complex issue at play. In this case, you may need to:

  • Consult the n8n documentation and community forums for more advanced troubleshooting guides.
  • Reach out to the MongoDB support team for assistance with database configuration or troubleshooting.
  • Escalate the issue to your organization's IT department or a professional services team for further assistance.
