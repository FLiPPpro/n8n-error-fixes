Slack node throws 'invalid_grant: Token has been expired or revoked' error

Error: invalid_grant: Token has been expired or revoked · Node: Slack

What this error actually means

When you encounter the invalid_grant error with the message "Token has been expired or revoked" in n8n, it means that the access token used to authenticate with the Slack API has either expired or been revoked. This can happen if the token was generated with a short lifespan, or if the user who authorized the token has revoked it.

The three most common causes

There are three common causes for this error:

  1. Expired token: The token was generated with a short lifespan and has expired.
  2. Token revocation: The user who authorized the token has revoked it.
  3. Incorrect token configuration: The token was not configured correctly in the Slack node.

Step-by-step fix

To fix this issue, follow these steps:

  1. Check the token configuration: Go to the Slack node's Settings tab and verify that the access token is correct and has not been revoked.
  2. Generate a new token: If the token has expired or been revoked, generate a new one by following the instructions in the Slack documentation.
  3. Update the token in n8n: Once you have generated a new token, update it in the Slack node's Settings tab.
  4. Configure retries: To handle cases where the token expires or is revoked, configure retries on the HTTP Request node. You can do this by going to the HTTP Request node's Settings tab and setting "Retry On Fail" to true, "Max Tries" to a suitable value, and "Wait Between Tries (ms)" to a suitable delay.

Here is an example of how to configure retries in a Code node:

{
  "name": "Configure retries",
  "parameters": {
    "retryOnFail": true,
    "maxTries": 3,
    "waitBetweenTriesMs": 30000
  },
  "type": "n8n-node-base"
}
  1. Add a delay: To add a delay before retrying, use the "Wait" node. You can add a delay of 30 seconds, for example, to give the token time to refresh.
  2. Branch on error: To handle cases where the token expires or is revoked, you can branch on error using the "Error Trigger" (real workflow trigger) or the "Continue On Fail" setting on a node.

Prevent it from coming back

To prevent this issue from coming back, make sure to:

  • Regularly update tokens: Regularly update the tokens in your Slack nodes to ensure they do not expire or get revoked.
  • Monitor token expiration: Monitor the expiration of tokens and update them before they expire.
  • Configure retries: Configure retries on the HTTP Request node to handle cases where the token expires or is revoked.

When to escalate

If you have tried the above steps and the issue persists, it may be necessary to escalate the issue to the n8n support team or the Slack support team for further assistance.
