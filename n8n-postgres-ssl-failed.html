n8n Postgres node fails due to SSL connection issue

Error: SSL connection is required · Node: Postgres

What this error actually means

When you encounter the "SSL connection is required" error in n8n while trying to connect to a Postgres database, it means that n8n is unable to establish a secure connection to the database using SSL/TLS encryption. This is a common issue that can arise due to various reasons, including incorrect SSL configuration, missing certificates, or issues with the database itself.

The three most common causes

Based on our experience, the three most common causes of this error are:

  1. Missing SSL certificates: Ensure that the SSL certificates are properly configured and installed on the Postgres database server. You can check the Postgres logs for any SSL-related errors.
  2. Incorrect SSL configuration: Verify that the SSL configuration in n8n matches the requirements of the Postgres database. This includes setting the correct SSL mode, certificate, and key.
  3. Database-specific issues: Check the Postgres database for any issues that might be preventing the SSL connection from being established. This could include issues with the database's SSL configuration or network connectivity problems.

Step-by-step fix

To resolve the "SSL connection is required" error, follow these steps:

  1. Check the Postgres logs: Verify that the Postgres logs do not contain any SSL-related errors. You can do this by checking the Postgres log files or by running the following SQL command:
SELECT pg_log_messages();
  1. Verify SSL certificates: Ensure that the SSL certificates are properly configured and installed on the Postgres database server. You can do this by checking the Postgres SSL configuration file (usually located at /etc/postgresql/ssl/pg_hba.conf).
  2. Configure SSL in n8n: In the n8n workflow, navigate to the Postgres node's Settings tab and configure the SSL settings as follows:

* Set the ssl option to true. * Enter the path to the SSL certificate file in the sslCert field. * Enter the path to the SSL key file in the sslKey field.

  1. Test the connection: After configuring the SSL settings, test the connection to the Postgres database by running the workflow.

Here is an example of how you can configure the SSL settings in the Postgres node's Settings tab:

{
  "name": "Postgres Node",
  "settings": {
    "ssl": true,
    "sslCert": "/path/to/ssl/cert",
    "sslKey": "/path/to/ssl/key"
  }
}
  1. Add a retry mechanism: To handle any temporary connection issues, add a retry mechanism to the workflow. You can do this by adding a Wait node with a short delay (e.g., 10 seconds) and then connecting it to the Postgres node. Configure the Postgres node to retry the connection after the delay.

Here is an example of how you can add a retry mechanism to the workflow:

{
  "nodes": [
    {
      "name": "Wait",
      "type": "wait",
      "settings": {
        "delay": 10000
      }
    },
    {
      "name": "Postgres Node",
      "type": "postgres",
      "settings": {
        "ssl": true,
        "sslCert": "/path/to/ssl/cert",
        "sslKey": "/path/to/ssl/key"
      }
    }
  ]
}

Prevent it from coming back

To prevent the "SSL connection is required" error from coming back, ensure that the SSL certificates are properly configured and installed on the Postgres database server. Regularly check the Postgres logs for any SSL-related errors and address them promptly.

When to escalate

If you have followed the above steps and the issue persists, it may be necessary to escalate the issue to the n8n support team or the Postgres database administrator. Provide as much detail as possible about the error, including any relevant logs or configuration files.
