n8n MySQL connection timed out waiting for query result

Error: Timeout error · Node: MySQL

What this error actually means

A "Timeout error" in n8n indicates that the node you're using to interact with your MySQL database has taken too long to complete its task. This can happen for a variety of reasons, including:

  • The database is slow to respond to queries
  • The query itself is taking a long time to execute
  • The network connection between n8n and the database is slow or unreliable

Regardless of the specific cause, the result is the same: your workflow is being halted because the node has timed out.

The three most common causes

Based on our experience, the three most common causes of timeout errors when querying a MySQL database in n8n are:

  1. Slow database queries: If your queries are taking a long time to execute, it can cause the node to timeout. This can be due to a variety of factors, including poorly written queries, inadequate indexing, or insufficient database resources.
  2. Network issues: If the network connection between n8n and the database is slow or unreliable, it can cause the node to timeout. This can be due to a variety of factors, including network congestion, firewall issues, or database server overload.
  3. Insufficient retry settings: If you're not configuring the node to retry failed queries, it can cause the node to timeout. This can be due to a variety of factors, including network issues, database errors, or poorly written queries.

Step-by-step fix

To fix a timeout error when querying a MySQL database in n8n, follow these steps:

  1. Check your database queries: Review your database queries to ensure they are well-written and optimized. Consider using EXPLAIN to analyze query performance.
  2. Configure retry settings: Configure the node to retry failed queries by setting "Retry On Fail" to true, "Max Tries" to a suitable value (e.g. 5), and "Wait Between Tries (ms)" to a suitable value (e.g. 5000).
  3. Add a delay: Consider adding a delay between retries using the "Wait" node. This can help prevent overwhelming the database with repeated queries.
  4. Use a Code node to retry queries: If you need more control over the retry process, consider using a Code node to write a JavaScript or Python script that retries queries.

Here's an example of how you can use a Code node to retry queries:

// Configure the retry settings
const retryCount = 5;
const retryDelay = 5000;

// Define the query to retry
const query = "SELECT * FROM mytable";

// Use a loop to retry the query
for (let i = 0; i < retryCount; i++) {
  try {
    // Execute the query
    const result = await db.query(query);
    // If the query succeeds, break out of the loop
    break;
  } catch (error) {
    // If the query fails, wait for the retry delay before trying again
    await new Promise(resolve => setTimeout(resolve, retryDelay));
  }
}
  1. Monitor your workflow: Monitor your workflow to ensure that the timeout error is resolved. You can do this by checking the workflow logs or using the "Error Trigger" to trigger an alert when a timeout error occurs.

Prevent it from coming back

To prevent a timeout error from recurring, consider the following:

  • Regularly review and optimize your database queries: Regularly review your database queries to ensure they are well-written and optimized. Consider using EXPLAIN to analyze query performance.
  • Monitor your database performance: Monitor your database performance to ensure it is not becoming overloaded or slow.
  • Configure your node settings: Configure your node settings to retry failed queries and add a delay between retries.

When to escalate

If you've tried the above steps and the timeout error persists, it may be necessary to escalate the issue to your database administrator or IT team. They may be able to provide additional guidance or assistance to resolve the issue.
