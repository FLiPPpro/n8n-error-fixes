HTTP Request Node Returns No Results

Error: HTTP request timed out · Node: HTTP Request

What this error actually means

When you see the error "HTTP request timed out" in n8n, it means that the HTTP Request node has reached its timeout limit and has not received a response from the server within that time. This can be due to various reasons such as a slow network connection, a server issue, or a problem with the request itself.

The three most common causes

Based on our experience, the three most common causes of this error are:

  1. Insufficient timeout settings: If the timeout settings on the HTTP Request node are too low, the node may time out before the server responds.
  2. Server issues: If the server is experiencing issues, it may not respond within the specified timeout period.
  3. Network connectivity problems: If there are issues with the network connection, the request may time out.

Step-by-step fix

To fix this issue, follow these steps:

  1. Check the timeout settings: Go to the HTTP Request node and check the "Timeout (ms)" setting. If it's too low, increase it to a higher value. For example, if you're making a request to a server that takes a few seconds to respond, set the timeout to at least 30,000ms (30 seconds).
  2. Check the retry settings: Go to the HTTP Request node and check the "Retry On Fail", "Max Tries", and "Wait Between Tries (ms)" settings. If the retry settings are not configured correctly, the node may not retry the request even if it times out.
  3. Add a delay: If you suspect that the server is taking too long to respond, you can add a delay using the "Wait" node. This will pause the workflow for a specified amount of time, allowing the server to respond.
  4. Check the request URL: Make sure the request URL is correct and that the server is reachable.

Here's an example of how you can add a delay using the "Wait" node:

{
  "name": "Wait 30 seconds",
  "type": "wait",
  "seconds": 30
}

You can add this node after the HTTP Request node to pause the workflow for 30 seconds.

Prevent it from coming back

To prevent this issue from coming back, follow these best practices:

  1. Monitor your server: Make sure your server is running smoothly and is not experiencing any issues.
  2. Monitor your network: Make sure your network connection is stable and not experiencing any issues.
  3. Test your workflow: Test your workflow regularly to ensure that it's working as expected.
  4. Increase timeout settings: Increase the timeout settings on the HTTP Request node to a higher value.

When to escalate

If you've tried the above steps and the issue persists, it's time to escalate. Reach out to your IT team or the server administrator to investigate the issue further. If the issue is with the server, it may require further investigation and troubleshooting to resolve.

If you're still experiencing issues, provide as much detail as possible about the error, including the error message, the workflow configuration, and any relevant logs. This will help the support team to investigate and resolve the issue more efficiently.
