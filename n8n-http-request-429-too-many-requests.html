n8n HTTP Request 429 Too Many Requests Error — How to Fix

Error: 429 Too Many Requests · Node: HTTP Request

What this error actually means

When you see the "429 Too Many Requests" error in n8n, it means that the external API you're trying to interact with has rate limited your requests. This is a common issue when working with APIs that have strict usage limits to prevent abuse.

The three most common causes

Before we dive into the fix, let's cover the most common reasons why you might be hitting rate limits:

  1. Insufficient retry configuration: If you're not configuring retries correctly on the HTTP Request node, you might be sending too many requests in a short period, triggering the rate limit.
  2. Inadequate wait time between requests: If you're not adding a sufficient delay between requests, you might be overwhelming the API with requests, causing the rate limit to be triggered.
  3. Incorrect API key or credentials: If you're using an API key or credentials to authenticate with the API, ensure they are correct and not causing the rate limit to be triggered.

Step-by-step fix

To fix the "429 Too Many Requests" error, follow these steps:

  1. Configure retries on the HTTP Request node: In the HTTP Request node, go to the Settings tab and set "Retry On Fail" to true. Set "Max Tries" to a reasonable value (e.g., 5) and "Wait Between Tries (ms)" to a sufficient delay (e.g., 10,000).
  2. Add a delay using the "Wait" node: Create a new "Wait" node and set the delay to a value that's greater than the "Wait Between Tries (ms)" value you set in step 1. This will add a delay between requests, giving the API time to recover.
  3. Configure the HTTP Request node to retry on error: In the HTTP Request node, go to the Settings tab and set "Retry On Fail" to true. Set "Max Tries" to a reasonable value (e.g., 5) and "Wait Between Tries (ms)" to a sufficient delay (e.g., 10,000).

Prevent it from coming back

To prevent the rate limit from being triggered again, make sure to:

  • Monitor your API usage and adjust your workflow accordingly.
  • Regularly review and update your API keys and credentials.
  • Implement a more sophisticated retry mechanism, such as exponential backoff.

When to escalate

If you've tried the above steps and the rate limit is still being triggered, it may be time to escalate the issue to the API provider or seek additional support from n8n's community or support team.
