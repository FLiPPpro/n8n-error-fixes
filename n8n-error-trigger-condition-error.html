n8n Error Trigger node fails with condition error message

Error: Condition error: node 'error' does not exist · Node: Error Trigger

What this error actually means

The error message "Condition error: node 'error' does not exist" is a common issue when using the Error Trigger node in n8n. This error occurs when the Error Trigger node is unable to find an error in the workflow's error data.

In n8n, the Error Trigger node is a workflow trigger that allows you to trigger a workflow based on an error condition. When an error occurs in a workflow, the error data is stored in the workflow's error data. The Error Trigger node checks this error data to determine if an error has occurred.

The three most common causes

There are three common causes for this error:

  1. No error data: The most common cause is that there is no error data available in the workflow's error data. This can happen if the workflow is not configured to store error data or if the error data is not being populated correctly.
  2. Error data not being populated: Another common cause is that the error data is not being populated correctly. This can happen if the workflow is not configured to store error data or if the error data is not being populated due to a configuration issue.
  3. Error Trigger node not configured correctly: The third common cause is that the Error Trigger node is not configured correctly. This can happen if the node is not configured to check for error data or if the node is not configured to trigger the workflow based on an error condition.

Step-by-step fix

To fix this error, you need to ensure that the Error Trigger node is configured correctly and that the error data is being populated correctly. Here are the steps to follow:

  1. Check the Error Trigger node configuration: Go to the Error Trigger node and check its configuration. Ensure that the node is configured to check for error data and that it is configured to trigger the workflow based on an error condition.
  2. Check the workflow configuration: Go to the workflow configuration and check if the workflow is configured to store error data. Ensure that the workflow is configured to store error data and that the error data is being populated correctly.
  3. Check the error data: Go to the workflow's error data and check if there is any error data available. Ensure that the error data is being populated correctly and that it is being populated due to a configuration issue.
  4. Use a Code node to populate error data: If the error data is not being populated correctly, you can use a Code node to populate the error data. Here is an example of how you can use a Code node to populate the error data:
// Populate error data
const error = {
  message: 'Error message',
  code: 'Error code'
};

// Set error data
workflow.set('error', error);
  1. Configure the Error Trigger node to check for error data: Once the error data is being populated correctly, configure the Error Trigger node to check for error data. Ensure that the node is configured to trigger the workflow based on an error condition.

Prevent it from coming back

To prevent this error from coming back, ensure that the Error Trigger node is configured correctly and that the error data is being populated correctly. Here are some tips to prevent this error:

  • Ensure that the workflow is configured to store error data.
  • Ensure that the error data is being populated correctly.
  • Configure the Error Trigger node to check for error data.
  • Use a Code node to populate error data if necessary.
