Postgres node throws 'invalid_grant: Token has been expired or revoked' error

Error: invalid_grant: Token has been expired or revoked · Node: Postgres

What this error actually means

The invalid_grant: Token has been expired or revoked error message indicates that the access token used by the Postgres node to authenticate with the database has expired or been revoked. This can happen due to various reasons such as token expiration time, token revocation, or incorrect token configuration.

The three most common causes

  1. Expired token: The token has reached its expiration time and is no longer valid.
  2. Token revocation: The token has been intentionally revoked by the database administrator or due to security reasons.
  3. Incorrect token configuration: The token is not properly configured or is not being refreshed correctly.

Step-by-step fix

To fix this issue, follow these steps:

  1. Check the token expiration time: Verify the token expiration time and ensure it is not set to a very short duration. You can do this by checking the expires_in field in the token response.
{
  "access_token": "...",
  "expires_in": 3600 // Token expires in 1 hour
}
  1. Refresh the token: If the token has expired, refresh it using the refresh token. You can do this by making a new request to the token endpoint with the refresh token.
curl -X POST \
  https://your-postgres-instance.com/oauth/token \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -d 'grant_type=refresh_token&refresh_token=your-refresh-token'
  1. Configure token refresh: Configure the Postgres node to refresh the token automatically when it expires. You can do this by setting the Retry On Fail option to true and configuring the Max Tries and Wait Between Tries (ms) options accordingly.
  2. Verify token configuration: Ensure that the token is properly configured and being refreshed correctly. You can do this by checking the token response and verifying that the access_token field is being updated correctly.

Prevent it from coming back

To prevent this issue from coming back, follow these best practices:

  1. Use a longer token expiration time: Set the token expiration time to a longer duration to reduce the frequency of token refreshes.
  2. Configure token refresh: Configure the Postgres node to refresh the token automatically when it expires.
  3. Monitor token status: Monitor the token status and refresh it manually if necessary.
  4. Implement token revocation: Implement token revocation mechanisms to ensure that tokens are properly revoked when no longer needed.

When to escalate

If you have followed the above steps and the issue persists, it may be necessary to escalate the issue to the n8n support team or the Postgres database administrator. Provide as much information as possible about the issue, including the error message, token configuration, and any relevant logs or screenshots.
