n8n HTTP Request node returns 403 Forbidden status code

Error: HTTP Request Node returned status code: 403 · Node: HTTP Request

What this error actually means

When you encounter the "HTTP Request Node returned status code: 403" error in n8n, it means that the HTTP request made by the node was denied due to a permission issue. This error is typically encountered when the API you're trying to fetch data from requires authentication or authorization, and the credentials provided in the HTTP Request node are incorrect or insufficient.

The three most common causes

There are several reasons why you might encounter this error:

  1. Incorrect API credentials: Make sure that the API key, username, and password (if applicable) are correctly entered in the HTTP Request node's Settings tab.
  2. Insufficient permissions: Ensure that the API credentials have the necessary permissions to access the requested resource.
  3. API rate limiting: If the API has rate limits, you might be hitting the limit, causing the 403 error.

Step-by-step fix

To resolve the 403 error, follow these steps:

  1. Verify API credentials: Double-check that the API key, username, and password (if applicable) are correctly entered in the HTTP Request node's Settings tab.
  2. Configure retry options: In the HTTP Request node's Settings tab, configure the "Retry On Fail" option to "Yes" and set the "Max Tries" to a reasonable value (e.g., 3). This will allow the node to retry the request up to the specified number of times.
  3. Add a delay: To add a delay between retries, use the "Wait" node (real) and configure it to wait for a certain amount of time (e.g., 5 seconds) between retries.
  4. Check API rate limiting: If you suspect that the API rate limiting is causing the issue, you can use the "Wait" node to add a delay between requests. For example, you can use the following JavaScript code in a Code node to add a 5-second delay between requests:
const delay = 5000; // 5 seconds
const currentTimestamp = new Date().getTime();
const delayUntil = currentTimestamp + delay;
while (new Date().getTime() < delayUntil) {
  // wait for the delay to expire
}
  1. Use the "Continue On Fail" setting: If you want to continue processing the workflow even if the HTTP Request node fails, configure the "Continue On Fail" setting to "Yes" in the HTTP Request node's Settings tab.

Prevent it from coming back

To prevent the 403 error from coming back, make sure to:

  • Regularly review and update your API credentials to ensure they are correct and up-to-date.
  • Monitor your API usage to avoid hitting rate limits.
  • Implement proper error handling and logging to detect and resolve issues promptly.

When to escalate

If you've tried the above steps and still encounter the 403 error, it's likely that the issue is related to the API itself or the credentials provided. In this case, you should:

  • Reach out to the API provider's support team to verify the credentials and permissions.
  • Review the API documentation to ensure you're using the correct endpoints and authentication methods.
  • Consider implementing additional error handling and logging to detect and resolve issues more efficiently.
