Telegram Send Node Error: TypeError: Cannot read properties of null

Error: TypeError: Cannot read properties of null (reading 'X') · Node: Telegram

What this error actually means

The error message "TypeError: Cannot read properties of null (reading 'X')" is a common issue in n8n workflows, especially when working with nodes that rely on external APIs or data sources. In this case, the error is occurring on the Telegram node, which is attempting to send a message with a null recipient.

This error is telling you that the Telegram node is trying to access a property (in this case, 'X') on a null value. This usually happens when the node is expecting a value to be present, but it's not.

The three most common causes

Based on our experience, the three most common causes of this error are:

  1. Missing or incorrect API credentials: Make sure that the Telegram node is properly configured with the correct API credentials. If the credentials are missing or incorrect, the node will not be able to access the Telegram API, leading to a null value.
  2. Invalid or missing recipient: Double-check that the recipient field in the Telegram node is properly populated. If the recipient is null or empty, the node will throw an error.
  3. Node configuration issues: Ensure that the Telegram node is properly configured, including the correct API endpoint, method, and authentication settings.

Step-by-step fix

To fix this issue, follow these steps:

  1. Check the recipient field: Verify that the recipient field in the Telegram node is properly populated. If it's null or empty, update the field with the correct recipient.
  2. Configure the Telegram node: Ensure that the Telegram node is properly configured, including the correct API endpoint, method, and authentication settings.
  3. Add a conditional statement: To prevent the error from occurring, add a conditional statement to check if the recipient field is null before attempting to send the message. You can use the "Error Trigger" workflow trigger or the "Continue On Fail" setting on the node to achieve this.

Here's an example code block that you can use in a "Code" node to add a conditional statement:

if ({{ recipient }} === null) {
  return { status: 'error', message: 'Recipient is null' };
}

This code checks if the recipient field is null, and if so, returns an error message. If the field is not null, the code continues to the next step.

  1. Update the Telegram node settings: Configure the Telegram node to retry the operation if it fails. You can do this by setting the "Retry On Fail" option to "Yes" and configuring the "Max Tries" and "Wait Between Tries (ms)" options.

Prevent it from coming back

To prevent this issue from occurring in the future, make sure to:

  • Regularly review and update your workflow configurations to ensure that all nodes are properly configured.
  • Use conditional statements to check for null or empty values before attempting to access them.
  • Configure nodes to retry operations if they fail.

When to escalate

If you've followed these steps and the issue persists, it may be necessary to escalate the issue to the n8n support team. Be sure to provide detailed information about the issue, including the error message, node configurations, and any relevant code.
