Gmail SMTP Error 535 Authentication Failed 2FA Blocking

Error: 535 Authentication failed · Node: Gmail

What this error actually means

The error message "535 Authentication failed" is a generic error message that can occur when the Gmail node is unable to authenticate with the Gmail account. This error is often caused by incorrect credentials or 2-factor authentication (2FA) settings.

The three most common causes

  1. Incorrect credentials: Double-check that the email address and password used in the Gmail node are correct. Make sure to use the correct password, including any special characters or uppercase/lowercase letters.
  2. 2FA settings: If your Gmail account has 2FA enabled, you need to configure the Gmail node to use an App Password or a custom authentication method. This is because the regular password is not sufficient to authenticate with the Gmail API.
  3. Gmail API settings: Ensure that the Gmail API is enabled for your account and that the necessary scopes are selected. You can do this by going to the Google Cloud Console and navigating to the API Library page.

Step-by-step fix

To fix the "535 Authentication failed" error, follow these steps:

  1. Enable 2-Step Verification (2SV) in the Gmail account: Go to your Gmail account settings and enable 2SV. This will add an extra layer of security to your account.
  2. Create an App Password: In the Gmail account settings, navigate to the "Signing into Google" section and click on "App passwords". Create a new App Password specifically for the n8n workflow. This password will be used to authenticate with the Gmail API.
  3. Configure the Gmail node: In the n8n workflow, navigate to the Gmail node and click on the "Settings" tab. In the "Authentication" section, select "OAuth" as the authentication method and paste the App Password created in step 2.
  4. Use a custom authentication method: If you don't want to use an App Password, you can configure a custom authentication method using a "Code" node. Create a new "Code" node and paste the following JavaScript code:
const axios = require('axios');

const auth = {
  type: 'OAuth',
  clientId: 'your_client_id',
  clientSecret: 'your_client_secret',
  refreshToken: 'your_refresh_token',
  accessToken: 'your_access_token'
};

const authHeaders = {
  headers: {
    'Authorization': `Bearer ${auth.accessToken}`,
    'Content-Type': 'application/json'
  }
};

axios.get('https://www.googleapis.com/gmail/v1/users/me/messages', authHeaders)
  .then(response => {
    console.log(response.data);
  })
  .catch(error => {
    console.error(error);
  });

Replace your_client_id, your_client_secret, your_refresh_token, and your_access_token with your actual credentials.

  1. Test the workflow: Save the changes and test the workflow to ensure that the Gmail node is able to authenticate successfully.

Prevent it from coming back

To prevent the "535 Authentication failed" error from coming back, make sure to:

  • Regularly review and update your credentials to ensure they are correct.
  • Use a secure method to store your credentials, such as an encrypted environment variable.
  • Monitor your workflow logs for any authentication errors and investigate the cause.

When to escalate

If you have followed the steps above and are still experiencing issues with the "535 Authentication failed" error, it may be necessary to escalate the issue to the n8n support team or a Google Cloud support specialist. Provide detailed logs and error messages to help diagnose the issue.
