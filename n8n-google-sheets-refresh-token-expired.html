n8n Google Sheets Refresh Token Expired — Fix

Error: invalid_grant: Token has been expired or revoked · Node: Google Sheets

What this error actually means

The invalid_grant: Token has been expired or revoked error in n8n is a common issue when using the Google Sheets node. This error occurs when the OAuth2 token used to authenticate with Google Sheets has expired or been revoked. There are three primary reasons for this error:

  • The Google 7-day testing cap has been reached, forcing you to re-authenticate.
  • You have changed your Google account password, invalidating the stored token.
  • Your Google app has not been verified, causing the token to be revoked.

The three most common causes

To troubleshoot this issue, it's essential to understand the underlying causes. Here are the three most common reasons for this error:

  1. Google 7-day testing cap: If you're using a Google account for testing purposes, you'll hit the 7-day limit for unverified apps. After this period, you'll need to re-authenticate to continue using the Google Sheets node.
  2. Password change: If you change your Google account password, the stored token in n8n will become invalid. You'll need to re-authenticate to update the token.
  3. App not verified: If your Google app hasn't been verified, the token will be revoked, causing the invalid_grant error.

Step-by-step fix

To resolve the invalid_grant error, follow these steps:

  1. Re-authenticate with Google Sheets:

* Go to the Google Sheets node in your n8n workflow. * Click on the "Settings" tab. * Scroll down to the "OAuth2" section. * Click on the "Re-authenticate" button. * Follow the prompts to re-authenticate with Google Sheets.

  1. Update the token:

* If you've changed your Google account password, update the token by re-authenticating. * If you're using a Google account for testing purposes, re-authenticate to update the token.

  1. Verify your Google app:

* Ensure your Google app has been verified by following the instructions in the Google Developers Console. * If your app hasn't been verified, re-authenticate to update the token.

To automate the re-authentication process, you can use a Code node to update the token. Here's an example JavaScript code block that you can paste into a Code node:

const google = require('googleapis').google;
const auth = new google.auth.GoogleAuth({
  client_id: 'YOUR_CLIENT_ID',
  client_secret: 'YOUR_CLIENT_SECRET',
  redirect_uri: 'YOUR_REDIRECT_URI',
});

const token = await auth.getAccessToken();
const refreshToken = await auth.getRefreshToken();

// Update the token in the n8n workflow
// Assuming the token is stored in a workflow variable named "googleToken"
const updateToken = {
  'googleToken': token,
  'googleRefreshToken': refreshToken,
};

// Update the token
return updateToken;

Replace YOUR_CLIENT_ID, YOUR_CLIENT_SECRET, and YOUR_REDIRECT_URI with your actual Google OAuth2 credentials.

Prevent it from coming back

To prevent the invalid_grant error from occurring in the future, follow these best practices:

  • Use a verified Google app: Ensure your Google app has been verified to avoid token revocation.
  • Use a service account: Consider using a service account to authenticate with Google Sheets, which can help avoid token revocation issues.
  • Monitor your token expiration: Keep an eye on your token expiration dates and re-authenticate before the token expires.

When to escalate
