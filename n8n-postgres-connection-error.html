n8n Postgres node connection error

Error: Error: Connection to Postgres database failed · Node: Postgres

What this error actually means

When you encounter the error "Error: Connection to Postgres database failed" in n8n, it means that n8n is unable to establish a connection to your Postgres database. This can be due to various reasons such as incorrect database credentials, network issues, or database down.

The three most common causes

Here are the three most common causes of this error:

  1. Incorrect database credentials: Make sure that the username, password, and host are correct in the Postgres node settings. Double-check that the database name and port are also correct.
  2. Postgres database down: Ensure that the Postgres database is up and running. You can check the Postgres status by running a command like psql -U -d . If the database is down, you'll need to resolve the issue with your Postgres administrator.
  3. Network issues: Verify that the network connection between n8n and the Postgres database is stable. Check your firewall settings and ensure that the Postgres port (usually 5432) is open.

Step-by-step fix

To fix the error, follow these steps:

  1. Check Postgres database credentials:
{
  "name": "Postgres",
  "type": "n8n",
  "database": "your_database_name",
  "username": "your_username",
  "password": "your_password",
  "host": "your_host",
  "port": 5432
}

Make sure that the credentials are correct and the database name, port, and host are also correct.

  1. Verify Postgres database status:
psql -U your_username -d your_database_name

If the database is down, you'll need to resolve the issue with your Postgres administrator.

  1. Check network connection:

Verify that the network connection between n8n and the Postgres database is stable. Check your firewall settings and ensure that the Postgres port (usually 5432) is open.

  1. Configure retry options:

Go to the Postgres node settings and configure the retry options:

  • Retry On Fail: Enable this option to retry the connection if it fails.
  • Max Tries: Set the maximum number of retries.
  • Wait Between Tries (ms): Set the delay between retries.

You can also use the "Wait" node to add a delay between retries:

{
  "name": "Wait",
  "type": "n8n",
  "delay": 10000 // 10 seconds
}

This will add a 10-second delay between retries.

  1. Use Error Trigger:

If the connection fails, you can use the Error Trigger to branch the workflow:

{
  "name": "Error Trigger",
  "type": "n8n",
  "conditions": {
    "error": {
      "type": "n8n",
      "status": 500
    }
  }
}

This will trigger the workflow to branch if the connection fails.

Prevent it from coming back

To prevent this error from coming back, make sure to:

  • Regularly check the Postgres database credentials and update them if necessary.
  • Verify the Postgres database status regularly.
  • Ensure that the network connection between n8n and the Postgres database is stable.

When to escalate

If you've tried the above steps and the error persists, it's time to escalate the issue. Reach out to your Postgres administrator to verify the database credentials and status. If the issue is with the network connection, contact your network administrator to resolve the issue. If none of the above steps resolve the issue, it's time to seek further assistance from the n8n community or support team.
