MySQL node reports connection lost error in n8n

Error: Error: Connection lost · Node: MySQL

What this error actually means

When you encounter the "Error: Connection lost" message in n8n while trying to connect to a MySQL database, it means that n8n has lost the connection to the database. This can happen due to various reasons such as network issues, database downtime, or incorrect database credentials.

The three most common causes

Based on our experience, the three most common causes of this error are:

  1. Network issues: This can be due to a temporary network outage or a misconfigured network setting.
  2. Database downtime: If the database is down or not responding, n8n will throw a "Connection lost" error.
  3. Incorrect database credentials: If the database credentials are incorrect or not properly configured, n8n will not be able to establish a connection to the database.

Step-by-step fix

To fix the "Error: Connection lost" error, follow these steps:

  1. Check the database credentials: Verify that the database credentials are correct and properly configured. Make sure the username, password, host, and port are correct.
  2. Check the network connection: Ensure that the network connection is stable and not experiencing any issues.
  3. Check the database status: Verify that the database is up and running. You can do this by checking the database logs or by using a tool like mysqladmin to check the database status.
  4. Configure retries: Configure the MySQL node to retry the connection. You can do this by going to the node's Settings tab and setting the "Retry On Fail" option to "Yes". Set the "Max Tries" option to the desired number of retries and the "Wait Between Tries (ms)" option to the desired delay between retries.

Here's an example of how you can configure the retries in the MySQL node:

{
  "name": "MySQL",
  "settings": {
    "retryOnFail": true,
    "maxTries": 3,
    "waitBetweenTries": 5000
  }
}
  1. Add a delay: If the database is down or not responding, you can add a delay to the workflow using the "Wait" node. This will pause the workflow for a specified amount of time, allowing the database to become available.

Here's an example of how you can add a delay of 30 seconds using the "Wait" node:

{
  "name": "Wait",
  "settings": {
    "seconds": 30
  }
}
  1. Branch on error: If the database connection fails, you can branch the workflow to a different path using the "Error Trigger" or the "Continue On Fail" setting on a node.

Prevent it from coming back

To prevent the "Error: Connection lost" error from coming back, make sure to:

  • Regularly check the database credentials and update them if necessary.
  • Monitor the database status and network connection to ensure they are stable.
  • Configure the retries in the MySQL node to retry the connection.
  • Add a delay to the workflow using the "Wait" node if the database is down or not responding.

When to escalate

If you have tried the above steps and the "Error: Connection lost" error persists, it may be necessary to escalate the issue to a database administrator or a network administrator to investigate and resolve the underlying issue.
