Telegram API Node Returns Error 429 Too Many Requests

Error: 429 Too many requests · Node: Telegram

What this error actually means

When you see a 429 error in n8n, it means that the Telegram API has rate limited your requests. This is a common issue when making API calls, especially if you're making multiple requests in a short amount of time. The Telegram API has a limit on the number of requests you can make per minute, and if you exceed this limit, you'll get a 429 error.

The three most common causes

There are three common causes for a 429 error in n8n when using the Telegram node:

  1. Making too many requests in a short amount of time: If you're making multiple requests to the Telegram API in a short amount of time, you may exceed the rate limit and get a 429 error.
  2. Using an outdated Telegram API token: If your Telegram API token is outdated, it may not be recognized by the Telegram API, leading to a 429 error.
  3. Configuring the Telegram node incorrectly: If the Telegram node is not configured correctly, it may make multiple requests to the Telegram API in a short amount of time, leading to a 429 error.

Step-by-step fix

To fix the 429 error, follow these steps:

  1. Check the Telegram API token: Make sure your Telegram API token is up-to-date and correct. You can check the token in the Telegram API settings.
  2. Configure the Telegram node correctly: Make sure the Telegram node is configured correctly, including the API token, endpoint, and any other required settings.
  3. Configure retries on the Telegram node: Go to the Telegram node's Settings tab and configure retries by setting "Retry On Fail" to true, "Max Tries" to a value higher than 1, and "Wait Between Tries (ms)" to a value that is at least 1 second.
  4. Add a delay between requests: If you're making multiple requests to the Telegram API, add a delay between requests using the "Wait" node. This will give the Telegram API time to process each request and prevent you from exceeding the rate limit.
  5. Write a custom retry logic: If you want more control over the retry logic, you can write a custom script using a "Code" node. Here's an example of how you can write a custom retry logic in JavaScript:
const telegramNode = nodes.get('Telegram');
const retryCount = 0;

function retryTelegram() {
  telegramNode.execute();
  retryCount++;
  if (retryCount < 3) {
    // Wait for 1 second before retrying
    new Wait({
      timeoutSeconds: 1
    }).on('done', retryTelegram);
  } else {
    // If we've reached the maximum number of retries, throw an error
    throw new Error('Maximum number of retries reached');
  }
}

retryTelegram();

This script will retry the Telegram node up to 3 times, waiting 1 second between each retry.

Prevent it from coming back

To prevent the 429 error from coming back, make sure to:

  • Use a valid and up-to-date Telegram API token
  • Configure the Telegram node correctly
  • Configure retries on the Telegram node
  • Add a delay between requests using the "Wait" node
  • Use a custom retry logic if needed

When to escalate

If you've tried the above steps and the 429 error persists, it may be a sign of a more serious issue with your Telegram API token or your n8n configuration. In this case, you should:

  • Check the Telegram API documentation to see if there are any known issues with the API token or your account
  • Reach out to the n8n community or support team for further assistance
  • Consider reaching out to the Telegram support team for help with your API token or account configuration.
