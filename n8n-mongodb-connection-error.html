MongoDB Node Connection Failed with Authentication Error

Error: Error: Authentication failed: Connection terminated due to connection timeout · Node: MongoDB

What this error actually means

When you see the error "Error: Authentication failed: Connection terminated due to connection timeout" in n8n, it means that the MongoDB node is unable to connect to your MongoDB instance due to authentication issues. This error is not related to the actual connection timeout, but rather to the authentication process failing.

The three most common causes

After analyzing various scenarios, we've identified the three most common causes of this error:

  1. Incorrect MongoDB credentials: Double-check that the username, password, and database name are correct in the MongoDB node's settings. Ensure that the credentials are up-to-date and match the ones used to connect to your MongoDB instance.
  2. Authentication method mismatch: Verify that the authentication method used in the MongoDB node (e.g., username/password, API key, or Kerberos) matches the one configured in your MongoDB instance.
  3. Network connectivity issues: Check that the n8n instance has a stable connection to the MongoDB instance. Ensure that the MongoDB instance is running and accessible from the n8n instance.

Step-by-step fix

To resolve the authentication failed error, follow these steps:

  1. Verify MongoDB credentials: Open the MongoDB node's settings and ensure that the username, password, and database name are correct. You can also try to connect to your MongoDB instance using the same credentials from a different tool (e.g., MongoDB Compass) to verify that the issue is specific to n8n.
  2. Configure authentication method: Verify that the authentication method used in the MongoDB node matches the one configured in your MongoDB instance. If you're using a different authentication method (e.g., API key), ensure that it's correctly set up in the MongoDB node.
  3. Add retry mechanism: To handle temporary connection issues, you can add a retry mechanism to the MongoDB node. You can do this by setting the "Retry On Fail" option to true and configuring the "Max Tries" and "Wait Between Tries (ms)" options according to your needs.

Here's an example of how to configure the retry mechanism using the MongoDB node's settings:

{
  "name": "MongoDB",
  "settings": {
    "username": "your_username",
    "password": "your_password",
    "database": "your_database",
    "retryOnFail": true,
    "maxTries": 3,
    "waitBetweenTries": 5000
  }
}

This configuration will retry the connection up to 3 times with a 5-second delay between retries.

  1. Verify network connectivity: Ensure that the n8n instance has a stable connection to the MongoDB instance. You can try to connect to your MongoDB instance from a different tool or service to verify that the issue is specific to n8n.

Prevent it from coming back

To prevent this error from recurring, consider the following:

  • Regularly review and update your MongoDB credentials to ensure they're up-to-date.
  • Verify that the authentication method used in the MongoDB node matches the one configured in your MongoDB instance.
  • Implement a monitoring system to detect and alert you to any connection issues or authentication failures.

When to escalate

If you've tried the above steps and the error persists, it's likely that the issue is more complex and requires further investigation. In this case, consider escalating the issue to:

  • Your MongoDB administrator to verify that the MongoDB instance is correctly configured and running.
  • Your n8n administrator to review the n8n instance's configuration and ensure that it's correctly set up to connect to your MongoDB instance.
  • The n8n support team for further assistance and guidance.
