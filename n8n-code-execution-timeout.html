n8n workflow Code node execution timeout error

Error: Execution timed out · Node: Code

What this error actually means

The "Execution timed out" error in n8n indicates that a workflow has stalled due to a node taking too long to execute. This can happen when a node is performing a resource-intensive operation, such as making a slow API call or executing a complex JavaScript function. When a node times out, the workflow will stop running and display the "Execution timed out" error message.

The three most common causes

Based on our experience, the three most common causes of the "Execution timed out" error are:

  1. Slow API calls: If a node is making a slow API call, it can cause the workflow to timeout. This can happen if the API server is unresponsive or if the API call is taking too long to complete.
  2. Resource-intensive operations: If a node is performing a resource-intensive operation, such as executing a complex JavaScript function or making a large number of API calls, it can cause the workflow to timeout.
  3. Incorrect node settings: If the node settings are not configured correctly, it can cause the workflow to timeout. For example, if the "Retry On Fail" setting is not enabled, the node will not retry the operation if it fails.

Step-by-step fix

To fix the "Execution timed out" error, follow these steps:

  1. Check the node settings: Check the node settings to see if the "Retry On Fail" setting is enabled. If not, enable it and set the "Max Tries" and "Wait Between Tries (ms)" settings to a reasonable value.
  2. Add a delay: If the node is making a slow API call, add a delay using the "Wait" node to give the API server time to respond.
  3. Optimize the node code: If the node is performing a resource-intensive operation, optimize the code to reduce the execution time. This can be done by using more efficient algorithms or by breaking down the operation into smaller tasks.
  4. Use a more efficient node: If the node is using a slow API library, consider switching to a more efficient library.
  5. Use a retry mechanism: If the node is making a slow API call, consider using a retry mechanism to retry the operation if it fails.

Here is an example of how to add a delay using the "Wait" node:

{
  "nodes": [
    {
      "name": "HTTP Request",
      "type": "http-request",
      "settings": {
        "url": "https://api.example.com",

        }

    {
      "name": "Wait",
      "type": "wait",
      "settings": {
        "duration": 10000
      }
    }
  ]
}

This code adds a 10-second delay after the HTTP request node has completed.

Prevent it from coming back

To prevent the "Execution timed out" error from coming back, follow these best practices:

  • Monitor your workflows: Monitor your workflows regularly to catch any issues before they cause a timeout.
  • Optimize your node code: Optimize your node code to reduce the execution time.
  • Use a retry mechanism: Use a retry mechanism to retry the operation if it fails.
  • Configure node settings correctly: Configure node settings correctly to avoid timeouts.

When to escalate

If you have tried the above steps and the "Execution timed out" error continues to occur, it may be necessary to escalate the issue to a n8n support specialist. Provide as much information as possible about the error, including:

  • Error message: Provide the exact error message.
  • Node settings: Provide the node settings, including any retry settings.
  • Node code: Provide the node code, including any custom code.
  • Workflow configuration: Provide the workflow configuration, including any custom settings.
