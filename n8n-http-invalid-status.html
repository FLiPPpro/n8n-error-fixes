n8n HTTP request error invalid status code

Error: HTTP status code not allowed for this request method · Node: HTTP Request

What this error actually means

The error message "HTTP status code not allowed for this request method" indicates that the HTTP request node in n8n is attempting to send a request with a status code that is not valid for the specified request method (e.g., GET, POST, PUT, DELETE, etc.). This can occur when the server returns an error status code that is not expected by the HTTP request node.

The three most common causes

Based on our experience, the three most common causes of this error are:

  1. Incorrect status code: The HTTP request node is configured to expect a specific status code, but the server returns a different one. This can happen when the server returns an error status code, such as 404 (Not Found) or 500 (Internal Server Error).
  2. Incompatible request method: The HTTP request node is configured to use a specific request method (e.g., GET, POST), but the server does not support this method for the specified endpoint.
  3. Server-side issues: The server is experiencing issues, such as maintenance, downtime, or configuration problems, which prevent it from returning a valid status code.

Step-by-step fix

To resolve this issue, follow these steps:

  1. Check the status code: Verify that the status code expected by the HTTP request node matches the one returned by the server. You can do this by checking the server's documentation or by inspecting the response in the n8n debug logs.
  2. Configure retries: If the issue is due to a temporary server-side problem, you can configure the HTTP request node to retry the request after a certain delay. To do this, go to the HTTP request node's Settings tab and enable "Retry On Fail" with a suitable "Max Tries" and "Wait Between Tries (ms)" value.
  3. Use a "Wait" node: If the issue is due to a server-side problem that requires a delay, you can add a "Wait" node to your workflow to pause the execution for a certain amount of time. This will allow the server to recover from its issue.
  4. Inspect the request: Verify that the request being sent by the HTTP request node is correct. You can do this by adding a "Code" node to your workflow with a JavaScript expression that logs the request details to the console.

Here's an example code block that you can use to log the request details to the console:

const request = n8n.nodes.HTTPRequest.getNode('HTTP Request').request;
console.log(request.method, request.url, request.headers);

This code block retrieves the request object from the HTTP request node and logs its method, URL, and headers to the console.

Prevent it from coming back

To prevent this issue from recurring, make sure to:

  1. Monitor server-side issues: Regularly check the server's status and documentation to ensure that it is functioning correctly.
  2. Configure retries: Enable retries on the HTTP request node to handle temporary server-side issues.
  3. Use a "Wait" node: Add a "Wait" node to your workflow to pause the execution in case of server-side issues.

When to escalate

If you have tried the above steps and the issue persists, it may be necessary to escalate the issue to the server administrators or the development team. Provide them with the following information:

  • The error message and any relevant logs
  • The request details, including the method, URL, headers, and body
  • The server's documentation and configuration
  • Any relevant workflow configurations and node settings

This will help them to diagnose and resolve the issue more efficiently.
