Webhook not registered HTTP 404 error in n8n

Error: The requested webhook is not registered · Node: Webhook

What this error actually means

The "The requested webhook is not registered" error in n8n occurs when you try to test a webhook URL after a workflow has stopped listening. This error is not related to the webhook itself, but rather to the workflow's configuration.

When a workflow is running, it listens for incoming webhooks and processes them accordingly. However, when the workflow stops running, it no longer listens for webhooks. If you try to test the webhook URL after the workflow has stopped, you'll get this error because the webhook is not registered.

The three most common causes

There are three common causes for this error:

  1. Workflow has stopped running: As mentioned earlier, if the workflow has stopped running, it will no longer listen for webhooks, resulting in this error.
  2. Webhook URL is incorrect: If the webhook URL is incorrect or not properly configured, the webhook will not be registered, leading to this error.
  3. Webhook is not properly configured: If the webhook is not properly configured in the workflow, it may not be registered correctly, resulting in this error.

Step-by-step fix

To fix this error, follow these steps:

  1. Check if the workflow is running: Make sure the workflow is running and listening for webhooks. If it's not running, start it.
  2. Verify the webhook URL: Double-check the webhook URL to ensure it's correct and properly configured.
  3. Configure the HTTP Request node: In the HTTP Request node, configure the "Retry On Fail" setting to true, set the "Max Tries" to a suitable number, and set the "Wait Between Tries (ms)" to a suitable delay. This will ensure that the HTTP Request node retries the request if it fails initially.

Here's an example code block you can use in a Code node to configure the retry settings:

{
  "retryOnFail": true,
  "maxTries": 3,
  "waitBetweenTries": 5000 // 5 seconds
}
  1. Add a Wait node: Add a Wait node to introduce a delay between retries. This will give the webhook time to register and process the request.
  2. Configure the Error Trigger: Configure the Error Trigger to branch on the error and continue the workflow if the request fails.

Prevent it from coming back

To prevent this error from coming back, make sure to:

  • Regularly check the workflow status: Regularly check the workflow status to ensure it's running and listening for webhooks.
  • Verify the webhook URL: Verify the webhook URL regularly to ensure it's correct and properly configured.
  • Configure the retry settings: Configure the retry settings in the HTTP Request node to ensure that the request is retried if it fails initially.

When to escalate

If you've tried the above steps and the error persists, it's time to escalate the issue. Check the n8n logs for any errors or warnings related to the webhook and workflow. If you're still unable to resolve the issue, reach out to the n8n community or support team for further assistance.
