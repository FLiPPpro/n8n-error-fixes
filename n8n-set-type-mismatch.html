n8n Set node type mismatch error message

Error: value is not of expected type · Node: Set

What this error actually means

When you encounter the "value is not of expected type" error in the Set node, it means that the value you're trying to set for a field does not match the expected data type. This can happen when the field is expecting a string, but you're passing a number, or vice versa.

The Set node is designed to update the values of fields in an object. It's a simple but powerful node that can be used to manipulate data in a workflow. However, when the data type of the value you're trying to set doesn't match the expected type, the node will throw an error.

The three most common causes

Based on our experience, the three most common causes of this error are:

  1. Data type mismatch: This is the most common cause of the error. When you're setting a field value, make sure that the data type of the value matches the expected type of the field.
  2. Incorrect field type: If you're using a field with a specific data type, such as a date or a boolean, make sure that the value you're setting is of the correct type.
  3. Nested objects: If you're working with nested objects, make sure that the value you're setting is an object with the correct structure.

Step-by-step fix

To fix the error, follow these steps:

  1. Check the field type: Make sure that the field type matches the data type of the value you're setting.
  2. Check the value type: Verify that the value you're setting is of the correct type.
  3. Use the correct syntax: If you're setting a field value using an expression, make sure that you're using the correct syntax.

Here's an example of how to fix the error using a Code node:

// Assuming you have a field called "name" of type string
// and you want to set its value to "John Doe"
const name = "John Doe";
const data = {
  name: name
};
return data;

In this example, we're setting the value of the "name" field to "John Doe", which is a string. Make sure that the field type matches the data type of the value.

Prevent it from coming back

To prevent the error from coming back, follow these best practices:

  • Use the correct data type: Make sure that the data type of the value you're setting matches the expected type of the field.
  • Use the correct syntax: Verify that you're using the correct syntax when setting field values using expressions.
  • Test your workflow: Test your workflow thoroughly to ensure that it's working as expected.

When to escalate

If you've tried the steps above and the error persists, it may be time to escalate the issue. This could involve:

  • Checking the n8n documentation: Make sure that you're using the correct nodes and options.
  • Checking the n8n community forums: See if others have encountered similar issues and how they resolved them.
  • Contacting n8n support: If you're still stuck, contact n8n support for further assistance.
