n8n Code execution error on script

Error: Execution error: ... ( stack trace ) · Node: Code

What this error actually means

When you encounter the "Execution error" in n8n, it means that the workflow has encountered an error while executing a node. This error can occur due to various reasons, such as incorrect node configuration, invalid data, or unexpected behavior from an external service. The error message will typically include a stack trace, which can provide valuable information about the exact location and cause of the error.

The three most common causes

Based on our experience, the three most common causes of the "Execution error" in n8n are:

  1. Incorrect node configuration: This can include misconfigured API endpoints, incorrect authentication credentials, or invalid data formats.
  2. External service issues: Problems with external services, such as API rate limits, timeouts, or unexpected errors, can cause the workflow to fail.
  3. Invalid data or logic: Incorrect data types, unexpected data formats, or logical errors in the workflow can also lead to execution errors.

Step-by-step fix

To troubleshoot and fix the "Execution error" in n8n, follow these steps:

  1. Check the node configuration: Review the node configuration to ensure that all settings are correct. Verify that API endpoints, authentication credentials, and data formats are accurate.
  2. Enable retries: Configure the node to retry failed operations by enabling "Retry On Fail" in the node's Settings tab. Set a reasonable number of retries (e.g., 3-5) and a suitable delay between retries (e.g., 1-2 seconds).
  3. Add a delay: Use the "Wait" node to introduce a delay between retries. This can help prevent overwhelming external services with repeated requests.
  4. Handle errors: Configure the node to continue on fail by enabling "Continue On Fail" in the node's Settings tab. This will allow the workflow to continue executing even if the node fails.
  5. Verify data: Ensure that the data being processed is valid and in the expected format. Use expressions or code nodes to validate data before processing it.

Prevent it from coming back

To prevent the "Execution error" from recurring, follow these best practices:

  1. Monitor and log errors: Set up logging and monitoring to track errors and identify patterns.
  2. Implement data validation: Use expressions or code nodes to validate data before processing it.
  3. Configure retries and delays: Set up retries and delays to prevent overwhelming external services.
  4. Regularly review and update workflows: Regularly review and update workflows to ensure they are accurate and efficient.

When to escalate

If you've followed the steps above and the "Execution error" persists, it's likely that the issue is more complex and requires further investigation. In this case, escalate the issue to your n8n support team or a senior engineer for further assistance. Provide as much detail as possible about the error, including the stack trace, node configuration, and any relevant data.
