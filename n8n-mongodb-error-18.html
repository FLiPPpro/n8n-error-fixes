MongoDB Node Returns Error 18 Connection Refused

Error: 18 Connection refused · Node: MongoDB

What this error actually means

The error message "18 Connection refused" is a clear indication that the MongoDB node in n8n is unable to establish a connection to your MongoDB database. This error typically occurs when the MongoDB node is unable to connect to the specified MongoDB instance, or when the MongoDB instance is not listening on the specified port.

The three most common causes

Based on our experience, the three most common causes of this error are:

  1. Incorrect MongoDB host or port: Make sure that the MongoDB host and port specified in the MongoDB node's settings are correct. Double-check that the host is the correct IP address or hostname of your MongoDB instance, and that the port is the correct port number (default is 27017).
  2. MongoDB instance not running or not listening on the specified port: Ensure that your MongoDB instance is running and listening on the specified port. You can check this by running mongo in your terminal and connecting to the instance.
  3. Firewall or network issues: Check that there are no firewall rules or network issues blocking the connection between the n8n workflow and the MongoDB instance.

Step-by-step fix

To fix this error, follow these steps:

  1. Check the MongoDB host and port: Open the MongoDB node's settings and verify that the host and port are correct. If you're using a MongoDB Atlas instance, make sure to use the correct host and port.
  2. Verify MongoDB instance is running and listening on the specified port: Run mongo in your terminal and connect to the instance using the specified host and port.
  3. Check firewall and network rules: Ensure that there are no firewall rules or network issues blocking the connection between the n8n workflow and the MongoDB instance.
  4. Configure the MongoDB node to retry the connection: In the MongoDB node's settings, configure the "Retry On Fail" option to true, set the "Max Tries" to a reasonable value (e.g., 5), and set the "Wait Between Tries (ms)" to a short value (e.g., 5000).

Here's an example code block that you can use to configure the MongoDB node to retry the connection:

{
  "name": "MongoDB",
  "settings": {
    "retryOnFail": true,
    "maxTries": 5,
    "waitBetweenTries": 5000
  }
}
  1. Run the workflow and verify the connection: Run the workflow and verify that the connection to the MongoDB instance is successful.

Prevent it from coming back

To prevent this error from coming back, make sure to:

  • Regularly verify that the MongoDB instance is running and listening on the specified port.
  • Monitor the n8n workflow logs for any errors or connection issues.
  • Update the MongoDB node's settings with the correct host and port.

When to escalate

If you've followed the steps above and the error persists, it's likely a more complex issue that requires further investigation. In this case, you should:

  • Check the MongoDB instance logs for any errors or issues.
  • Verify that the n8n workflow has the necessary permissions to connect to the MongoDB instance.
  • Reach out to your MongoDB administrator or n8n support team for further assistance.
