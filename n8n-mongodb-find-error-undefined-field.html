MongoDB Find Node Error: TypeError: Cannot read properties of undefined

Error: TypeError: Cannot read properties of undefined (reading 'X') · Node: MongoDB

What this error actually means

When you encounter the TypeError: Cannot read properties of undefined (reading 'X') error in n8n, it means that the node you're working with is trying to access a property of an object that doesn't exist. In this case, the error is specifically related to a MongoDB node, which is trying to filter results based on a field that doesn't exist.

The three most common causes

There are three common causes for this error:

  1. Field does not exist in the MongoDB collection: This is the most common cause. If the field you're trying to filter by doesn't exist in the MongoDB collection, the error will occur.
  2. Typo in field name: Make sure you've typed the field name correctly. A single typo can cause the error.
  3. Incorrect data type: If the field exists but has a different data type than expected, the error can occur.

Step-by-step fix

To fix this error, follow these steps:

  1. Check the MongoDB collection: Make sure the field you're trying to filter by exists in the MongoDB collection. You can do this by running a simple query in the MongoDB shell or using a tool like MongoDB Compass.
  2. Verify the field name: Double-check the field name to ensure it's correct. If you're using a variable, make sure it's correctly defined.
  3. Use the exists operator: Instead of trying to filter by a field that doesn't exist, use the $exists operator to check if the field exists. You can do this in the MongoDB node's settings by adding a new filter.

Here's an example code block that demonstrates how to use the $exists operator:

{
  "filter": {
    "name": {
      "$exists": true
    }
  }
}

In this example, we're checking if the name field exists in the collection. If it does, the filter will be applied.

If you're using a variable to store the field name, you can use the following code block in a Code node:

const fieldName = 'name'; // replace with your variable
const filter = {
  filter: {
    [fieldName]: {
      "$exists": true
    }
  }
};
return filter;

Prevent it from coming back

To prevent this error from occurring again, make sure to:

  • Verify the field name and data type before trying to filter by it.
  • Use the $exists operator to check if the field exists.
  • Test your workflow thoroughly to catch any errors before deploying it to production.

When to escalate

If you've tried the above steps and still encounter the error, it's time to escalate the issue. Reach out to the n8n community or your organization's support team for further assistance. Provide as much detail as possible about the error, including the node configuration, workflow settings, and any relevant logs.
