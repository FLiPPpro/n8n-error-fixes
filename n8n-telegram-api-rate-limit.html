Telegram Bot API rate limit exceeded in n8n workflow

Error: rateLimiter: Rate limit exceeded · Node: Telegram

What this error actually means

When you see the rateLimiter: Rate limit exceeded error message in n8n, it means that the Telegram API has blocked your requests due to excessive usage. This is a common issue when working with APIs that have rate limits, and it's essential to address it to avoid further errors and ensure your workflow's reliability.

The three most common causes

There are three primary reasons why this error occurs:

  1. Insufficient delay between requests: When sending multiple requests to the Telegram API in quick succession, you might exceed the rate limit. This is particularly common when using a loop or a scheduling node to send messages at regular intervals.
  2. Inadequate retry configuration: If you're not configuring the retry options correctly on the node, you might not be giving the API enough time to recover between requests.
  3. Incorrect Telegram API configuration: If your Telegram API credentials are not set up correctly, you might be sending requests with an incorrect rate limit, leading to this error.

Step-by-step fix

To resolve the rateLimiter: Rate limit exceeded error, follow these steps:

  1. Configure the retry options:

* Open the Telegram node's Settings tab. * Set "Retry On Fail" to true. * Configure the "Max Tries" and "Wait Between Tries (ms)" options according to your needs. * You can also configure the retry options directly on the HTTP Request node.

  1. Add a delay between requests:

* Insert a "Wait" node (real) between the Telegram node and the next node in your workflow. * Set the "Wait" node's duration to a value that's significantly longer than the Telegram API's rate limit (e.g., 60 seconds).

  1. Use a loop with a delay:

* If you're using a loop to send messages, add a "Wait" node (real) inside the loop to introduce a delay between each iteration. * This will help prevent excessive requests to the Telegram API.

  "nodes": [

This code block adds a "Wait" node (real) with a duration of 60 seconds (60000 milliseconds) between the Telegram node and the next node in your workflow.

Prevent it from coming back

To prevent this error from occurring in the future, make sure to:

  • Monitor your workflow's performance and adjust the retry options and delay between requests accordingly.
  • Regularly review your Telegram API credentials and configuration to ensure they're set up correctly.
  • Consider implementing a more robust retry mechanism, such as using a separate node to handle retries or implementing a custom retry logic using a "Code" node (JavaScript or Python).

When to escalate

If you've tried the above steps and the error persists, it's likely that the issue is more complex and requires further investigation. In this case, consider escalating the issue to the n8n support team or seeking help from a qualified developer who's familiar with n8n and the Telegram API. Provide as much detail as possible about your workflow, including the node configurations, error messages, and any relevant logs.
