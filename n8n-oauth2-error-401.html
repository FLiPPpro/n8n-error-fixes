OAuth2 Node Returns Error 401 Unauthorized

Error: 401 Unauthorized · Node: OAuth2

What this error actually means

When you encounter a 401 Unauthorized error in n8n, it means the OAuth2 node is unable to authenticate with the OAuth2 server. This error typically occurs when the credentials provided in the OAuth2 node are incorrect or when the OAuth2 server is not configured correctly.

The three most common causes

After troubleshooting many n8n workflows, we've identified the following three common causes for the 401 Unauthorized error:

  1. Incorrect OAuth2 credentials: Double-check that the Client ID, Client Secret, and Authorization URL are correctly entered in the OAuth2 node.
  2. OAuth2 server configuration issues: Verify that the OAuth2 server is correctly configured and that the redirect URI matches the one specified in the OAuth2 node.
  3. Token expiration or invalid token: Ensure that the access token is valid and not expired. You can check the token expiration time by inspecting the token response from the OAuth2 server.

Step-by-step fix

To fix the 401 Unauthorized error, follow these steps:

  1. Verify OAuth2 credentials:

* Go to the OAuth2 node and check the Client ID, Client Secret, and Authorization URL. * Ensure that these values are correctly entered and match the OAuth2 server configuration.

  1. Check OAuth2 server configuration:

* Verify that the OAuth2 server is correctly configured and that the redirect URI matches the one specified in the OAuth2 node. * Check the OAuth2 server documentation for any specific configuration requirements.

  1. Check token expiration or invalid token:

* Inspect the token response from the OAuth2 server to check the token expiration time. * If the token is expired, obtain a new token using the refresh token (if available).

  1. Configure retry options:

* Go to the OAuth2 node and configure the retry options via the Settings tab: + Set "Retry On Fail" to true. + Set "Max Tries" to a reasonable value (e.g., 3). + Set "Wait Between Tries (ms)" to a suitable value (e.g., 5000).

Here's an example code block that you can use in a Code node to check the token expiration time:

const tokenResponse = {{tokenResponse}};
const tokenExpirationTime = tokenResponse.expires_in;
const currentTime = new Date().getTime();
if (currentTime > tokenExpirationTime) {
  // Obtain a new token using the refresh token (if available)
  const refreshToken = {{refreshToken}};
  const newTokenResponse = await fetch('https://oauth2-server.com/token', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/x-www-form-urlencoded'
    },
    body: `grant_type=refresh_token&refresh_token=${refreshToken}`
  });
  const newToken = await newTokenResponse.json();
  // Update the access token in the OAuth2 node
  {{updateAccessToken(newToken.access_token)}}
}

Note: Replace the placeholders ({{tokenResponse}}, {{refreshToken}}, and {{updateAccessToken(newToken.access_token)}}) with the actual values from your OAuth2 node.

Prevent it from coming back

To prevent the 401 Unauthorized error from occurring again, ensure that:

  • The OAuth2 credentials are correctly entered and match the OAuth2 server configuration.
  • The OAuth2 server is correctly configured and the redirect URI matches the one specified in the OAuth2 node.
  • The access token is valid and not expired.

When to escalate

If you've tried the above steps and the 401 Unauthorized error persists, it's likely a more complex issue that requires further investigation. In this case, escalate the issue to the n8n support team, providing as much detail as possible about your workflow, OAuth2 server configuration, and error messages.
