Slack Web API Retry-After header not respected

Error: retry_after: 120 · Node: Slack

What this error actually means

When you encounter the retry_after: 120 error in n8n, it means that the Slack API is rejecting your request due to rate limiting. The retry_after value indicates the number of seconds you must wait before making another request. This error is not a n8n-specific issue, but rather a response from the Slack API.

The three most common causes

Before diving into the fix, let's cover the three most common causes of this error:

  1. Excessive requests: If you're making too many requests to the Slack API in a short period, you'll hit the rate limit, causing this error.
  2. Incorrect API token: Using an invalid or expired API token can lead to rate limiting issues.
  3. Insufficient wait time: Not waiting long enough between requests can cause the API to reject your request.

Step-by-step fix

To fix this issue, follow these steps:

  1. Check your API token: Ensure you're using a valid and up-to-date API token. If you're using an expired token, update it to resolve the issue.
  2. Adjust your workflow: If you're making excessive requests, consider adding a delay between requests using the Wait node. This will give the API time to process your requests and prevent rate limiting.
  3. Configure retry settings: Go to the HTTP Request node's Settings tab and configure the retry settings:

* Set Retry On Fail to true. * Set Max Tries to a value higher than the current retry limit (e.g., 3). * Set Wait Between Tries (ms) to a value that allows for sufficient delay between retries (e.g., 10,000 ms).

  1. Add a delay: If you're not using the HTTP Request node, you can add a Wait node to introduce a delay between requests. For example:
{
  "name": "Wait 10 seconds",
  "type": "wait",
  "seconds": 10
}
  1. Configure error handling: To handle errors and prevent the workflow from failing, configure the HTTP Request node's Continue On Fail setting to true. This will allow the workflow to continue executing even if the request fails.

Prevent it from coming back

To prevent this issue from recurring, consider the following:

  • Monitor your API usage: Keep an eye on your API usage to ensure you're not exceeding the rate limit.
  • Implement rate limiting: If you're making excessive requests, consider implementing rate limiting in your workflow to prevent overloading the API.
  • Update your API token: Regularly update your API token to prevent expired tokens from causing issues.

When to escalate

If you've tried the above steps and the issue persists, it's likely a problem with your API token or a configuration issue. In this case, contact the Slack API support team to investigate further. Provide them with the retry_after value and any relevant logs or error messages. If you're still unsure about how to resolve the issue, consider reaching out to the n8n community or seeking assistance from a n8n expert.
