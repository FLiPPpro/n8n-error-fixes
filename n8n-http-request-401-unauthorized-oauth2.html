n8n HTTP Request 401 Unauthorized with OAuth2 — Fix

Error: 401 Unauthorized · Node: HTTP Request

What this error actually means

When you encounter the "401 Unauthorized" error in n8n's HTTP Request node, it means that the node is unable to authenticate with the target server. This error is often caused by an issue with the OAuth2 credentials, but it can also be due to other factors such as an expired token, missing scope, or incorrect credential selection.

The three most common causes

There are three primary causes of the "401 Unauthorized" error in the HTTP Request node:

  1. Expired token: If the token used for authentication has expired, the server will reject the request. This can happen if the token's expiration time is not properly set or if it has been manually revoked.
  2. Missing scope: If the OAuth2 credentials do not include the required scope for the request, the server will reject the request. This can happen if the scope is not properly configured in the credentials or if the credentials are not updated to include the required scope.
  3. Wrong credential selection: If the wrong OAuth2 credentials are selected, the node will attempt to authenticate with the wrong server or with incorrect credentials. This can happen if the credentials are not properly configured or if the wrong credentials are selected.

Step-by-step fix

To fix the "401 Unauthorized" error, follow these steps:

  1. Check the token expiration: Check the token's expiration time and ensure that it has not expired. If the token has expired, you will need to obtain a new token.
  2. Verify the scope: Verify that the OAuth2 credentials include the required scope for the request. If the scope is missing, update the credentials to include the required scope.
  3. Check the credential selection: Check that the correct OAuth2 credentials are selected. If the wrong credentials are selected, update the credentials to the correct ones.
  4. Configure retry options: Configure the retry options on the HTTP Request node to attempt to authenticate again. You can do this by setting the "Retry On Fail" option to "true" and configuring the "Max Tries" and "Wait Between Tries (ms)" options.
  5. Use a Code node to verify the token: Use a Code node to verify the token and ensure that it is valid. You can use the following JavaScript code in a Code node to verify the token:
const token = credentials.oauth2AccessToken;
const tokenInfo = await fetch(`https://oauth2.googleapis.com/tokeninfo?id_token=${token}`);
const tokenInfoJson = await tokenInfo.json();
if (tokenInfoJson.error) {
  throw new Error(`Invalid token: ${tokenInfoJson.error}`);
}

This code fetches the token info from the Google OAuth2 server and checks if the token is valid. If the token is invalid, it throws an error.

Prevent it from coming back

To prevent the "401 Unauthorized" error from coming back, make sure to:

  • Regularly update the OAuth2 credentials to include the required scope.
  • Monitor the token expiration and obtain a new token before it expires.
  • Use a Code node to verify the token and ensure that it is valid.
  • Configure the retry options on the HTTP Request node to attempt to authenticate again.

When to escalate

If you have tried the above steps and the "401 Unauthorized" error persists, it may be necessary to escalate the issue to the n8n support team or the server administrator. Provide as much information as possible about the error, including the error message, the node configuration, and any relevant logs.
