n8n workflow Webhook node 408 Request Timeout error

Error: 408 Request Timeout · Node: Webhook

What this error actually means

The 408 Request Timeout error in n8n indicates that the Webhook node request timed out before it could complete. This can happen when the request takes longer than expected to process, or if the server is experiencing high latency or unresponsiveness. As a result, the n8n workflow fails, and the data is not processed further.

The three most common causes

After analyzing numerous cases of the 408 Request Timeout error, we've identified the following three common causes:

  1. Insufficient retry settings: If the Webhook node is configured to retry on failure, but the retry settings are too aggressive, it can lead to a timeout error. This is because the node keeps retrying the request without giving up, even if it's taking longer than expected.
  2. Server-side issues: If the server hosting the Webhook node is experiencing high latency or unresponsiveness, it can cause the request to timeout. This could be due to various reasons such as server overload, network congestion, or even a misconfigured server.
  3. Incorrect request settings: If the request settings in the Webhook node are not properly configured, it can lead to a timeout error. For example, if the request timeout is set too low, the node will timeout even if the server is responding slowly.

Step-by-step fix

To fix the 408 Request Timeout error, follow these steps:

  1. Check the retry settings: Go to the Webhook node's Settings tab and check the "Retry On Fail" setting. If it's enabled, adjust the "Max Tries" and "Wait Between Tries (ms)" settings to a more conservative value. You can also try disabling the retry setting altogether to see if it resolves the issue.
  2. Add a delay: Use the "Wait" node to introduce a delay before the Webhook node request. This can help prevent the request from timing out due to server-side issues. For example, you can add a 10-second delay before the Webhook node request using the following code in a Code node (JavaScript):
const delay = 10000; // 10 seconds
return new Promise(resolve => setTimeout(resolve, delay));
  1. Configure the request settings: Go to the Webhook node's Settings tab and check the request timeout setting. If it's set too low, increase it to a more reasonable value. You can also try adjusting the request timeout to a higher value, such as 30 seconds or 1 minute.
  2. Monitor server-side issues: If you suspect that the issue is server-side, monitor the server's performance and adjust the retry settings or request settings accordingly.

Prevent it from coming back

To prevent the 408 Request Timeout error from recurring, follow these best practices:

  • Monitor server-side performance: Regularly monitor the server's performance and adjust the retry settings or request settings accordingly.
  • Adjust retry settings: Adjust the retry settings to a more conservative value to prevent the node from retrying the request indefinitely.
  • Use a more robust request timeout: Increase the request timeout to a more reasonable value to prevent the node from timing out due to server-side issues.

When to escalate

If you've tried the above steps and the issue persists, it's likely that the problem is more complex and requires further investigation. In this case, escalate the issue to your n8n support team or a senior engineer for further assistance. Provide as much detail as possible about the issue, including the error message, node configurations, and any relevant logs.
