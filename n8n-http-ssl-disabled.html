n8n HTTP Request node returns SSL disabled error

Error: SSL connection is required · Node: HTTP Request

What this error actually means

When you encounter the "SSL connection is required" error in n8n, it means that the HTTP Request node is unable to establish a secure connection with the server you're trying to fetch data from. This is because the server requires a secure connection (HTTPS) to protect the data being transmitted. n8n's HTTP Request node will only attempt to connect using HTTPS if you've specified the correct protocol in the node's settings.

The three most common causes

There are three common reasons why you might encounter this error:

  1. Incorrect protocol specified: Make sure you've specified the correct protocol (HTTPS) in the node's settings. If you've specified HTTP instead, n8n will try to connect using an insecure connection.
  2. Server requires a specific SSL/TLS version: Some servers may require a specific SSL/TLS version to be used for the connection. If n8n's default SSL/TLS version is not compatible with the server, you may need to specify a different version.
  3. Certificate issues: There may be issues with the SSL/TLS certificate used by the server, such as an expired or invalid certificate.

Step-by-step fix

To fix this error, follow these steps:

  1. Check the protocol: Ensure that the protocol specified in the node's settings is HTTPS. If it's not, change it to HTTPS.
  2. Check the SSL/TLS version: If you're using a specific SSL/TLS version, ensure that it's compatible with the server. You can specify the SSL/TLS version in the node's settings.
  3. Verify the certificate: Check the SSL/TLS certificate used by the server to ensure it's valid and not expired.

Here's an example of how to specify the correct protocol and SSL/TLS version in the node's settings:

{
  "name": "HTTP Request",
  "settings": {
    "method": "GET",
    "url": "https://example.com/api/data",
    "options": {
      "rejectUnauthorized": true,
      "secureOptions": 2 // Specify the correct SSL/TLS version
    }
  }
}

In this example, we're specifying the correct protocol (HTTPS) and setting the rejectUnauthorized option to true to ensure that the connection is secure. We're also specifying the correct SSL/TLS version using the secureOptions option.

Prevent it from coming back

To prevent this error from coming back, make sure to:

  • Regularly check the SSL/TLS certificate used by the server to ensure it's valid and not expired.
  • Update the SSL/TLS version used by n8n to ensure it's compatible with the server.
  • Monitor the connection logs to detect any issues with the SSL/TLS connection.

When to escalate

If you've tried the above steps and the error persists, it may be worth escalating the issue to the server administrators to ensure that the server is configured correctly and that there are no issues with the SSL/TLS certificate. Additionally, if you're using a custom SSL/TLS version, it may be worth consulting the documentation for that version to ensure that it's compatible with the server.
