n8n Webhook node rate limit error

Error: Rate Limit: Webhook has exceeded the maximum allowed requests · Node: Webhook

What this error actually means

The "Rate Limit: Webhook has exceeded the maximum allowed requests" error in n8n indicates that the webhook you're trying to send requests to has reached its rate limit. This means that the number of requests you're sending to the webhook exceeds the maximum allowed by the webhook's provider. This can happen when you're sending a high volume of requests to the webhook, or if the webhook's rate limit is too low.

The three most common causes

Based on our experience, the three most common causes of this error are:

  1. Insufficient rate limit configuration: If you're not configuring the rate limit correctly on the node, you may be sending too many requests to the webhook, exceeding its rate limit.
  2. Inadequate retry configuration: If you're not configuring retries correctly on the node, you may be trying to send requests to the webhook too quickly, exceeding its rate limit.
  3. High volume of requests: If you're sending a high volume of requests to the webhook, you may be exceeding its rate limit, even if you have the rate limit and retry configuration set correctly.

Step-by-step fix

To fix this error, you'll need to configure the rate limit and retry configuration correctly on the node. Here's a step-by-step guide:

  1. Configure the rate limit: Go to the node's Settings tab and set the "Rate Limit" field to the maximum number of requests allowed by the webhook's provider. You can find this information in the webhook's documentation.
  2. Configure retries: Go to the node's Settings tab and set the "Retry On Fail" field to "true". Set the "Max Tries" field to the number of times you want the node to retry sending the request. Set the "Wait Between Tries (ms)" field to the amount of time you want to wait between retries.
  3. Add a delay: To add a delay between retries, you can use the "Wait" node. Create a new "Wait" node and set the "Duration" field to the amount of time you want to wait between retries.
  4. Branch on error: To branch on error, you can use the "Error Trigger" workflow trigger. Create a new "Error Trigger" node and set the "Error" field to the error message you want to trigger on.
  5. Write a retry function: To write a retry function, you can use the "Code" node. Here's an example of a retry function in JavaScript:
function retryRequest(node, callback) {
  const maxTries = node.settings.maxTries;
  const waitBetweenTries = node.settings.waitBetweenTries;
  let tries = 0;

  function sendRequest() {
    // Send the request to the webhook
    // ...

    // If the request fails, retry after the specified wait time
    if (tries < maxTries) {
      setTimeout(sendRequest, waitBetweenTries);
      tries++;
    } else {
      // If the maximum number of retries is reached, fail the node
      callback(new Error('Maximum number of retries reached'));
    }
  }

  sendRequest();
}

Prevent it from coming back

To prevent this error from coming back, you'll need to monitor the rate limit and retry configuration of the node. Here are some tips:

  • Monitor the rate limit: Keep an eye on the rate limit of the webhook's provider and adjust the rate limit configuration of the node accordingly.
  • Monitor the retry configuration: Keep an eye on the retry configuration of the node and adjust it accordingly to prevent excessive retries.
  • Use a load balancer: Consider using a load balancer to distribute the traffic to the webhook and prevent excessive requests from being sent to the webhook.

When to escalate

If you're experiencing this error and have tried the steps above, it's likely that the issue is more complex and requires further investigation. In this case, you should escalate the issue to your team's lead or a senior engineer for further assistance.
