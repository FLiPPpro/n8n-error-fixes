HTTP Request node causing memory leak in n8n workflow

Error: Error: Memory leak detected in node 'HTTP Request' · Node: HTTP Request

What this error actually means

The "Memory leak detected in node 'HTTP Request'" error message indicates that the HTTP Request node is consuming increasing amounts of memory, causing the workflow to slow down or even crash. This issue is likely due to the node not being properly configured to handle failed requests, leading to a buildup of memory usage over time.

The three most common causes

Based on our experience, the three most common causes of this error are:

  1. Insufficient retry settings: If the HTTP Request node is not configured to retry failed requests, it will continue to consume memory as it attempts to send the request again and again.
  2. Missing error handling: If the node is not configured to handle errors properly, it will not be able to release the memory it has allocated, leading to a memory leak.
  3. Infinite loops: If the HTTP Request node is not properly configured, it can create an infinite loop of requests, causing the memory usage to increase exponentially.

Step-by-step fix

To fix this issue, follow these steps:

  1. Configure retry settings: Go to the HTTP Request node's Settings tab and set the "Retry On Fail" option to "Yes". Set the "Max Tries" option to a reasonable number (e.g., 3-5). Set the "Wait Between Tries (ms)" option to a small value (e.g., 100-500).
  2. Add error handling: Go to the HTTP Request node's Settings tab and set the "Continue On Fail" option to "Yes". This will allow the node to continue running even if the request fails.
  3. Add a delay: Add a "Wait" node after the HTTP Request node to introduce a delay between requests. This will give the node a chance to release any allocated memory.
  4. Configure the node to handle errors: Go to the HTTP Request node's Settings tab and set the "Error Handling" option to "Continue". This will allow the node to continue running even if an error occurs.

Here's an example of how you can configure the retry settings using a Code node:

{
  "retryOnFail": true,
  "maxTries": 3,
  "waitBetweenTries": 100
}

You can paste this code into a Code node and set it as an expression for the HTTP Request node's "Retry Settings" field.

Prevent it from coming back

To prevent this issue from coming back, make sure to:

  • Regularly review and update your workflow to ensure that it is properly configured and optimized.
  • Monitor your workflow's memory usage and adjust the retry settings and error handling as needed.
  • Consider adding additional error handling and logging to help diagnose and fix issues.

When to escalate

If you've followed the steps above and the issue persists, it's likely that there's a more complex issue at play. In this case, you should:

  • Reach out to the n8n community for further assistance and guidance.
  • Review the n8n documentation and forums to see if others have experienced similar issues.
  • Consider seeking help from a n8n expert or consultant to help resolve the issue.
