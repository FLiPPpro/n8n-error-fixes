Google Sheets Read Node Error: TypeError: Cannot read properties of null

Error: TypeError: Cannot read properties of null (reading 'X') · Node: Google Sheets

What this error actually means

When you encounter the TypeError: Cannot read properties of null (reading 'X') error in n8n, it means that the node trying to read from a Google Sheets spreadsheet is encountering a null value in the spreadsheet. Specifically, it's trying to read a property X from a null value, which is causing the error.

This error is not specific to Google Sheets, but rather a general JavaScript error that can occur when trying to access properties of a null or undefined value.

The three most common causes

Based on our experience with n8n, the three most common causes of this error are:

  1. Incorrect spreadsheet range: Make sure you're specifying the correct range for the Google Sheets node. If the range is empty or null, you'll get this error.
  2. Null or empty cell values: If the spreadsheet contains null or empty cell values, the node will throw this error when trying to read them.
  3. Misconfigured node settings: Double-check the node settings, especially the "Range" field, to ensure it's correctly configured.

Step-by-step fix

To fix this error, follow these steps:

  1. Verify the spreadsheet range: Check the "Range" field in the Google Sheets node to ensure it's correctly specified. If it's empty or null, update it to the correct range.
  2. Add a null check: To prevent the error from occurring, add a null check in the "Code" node. You can use the following JavaScript code:
const spreadsheet = credentials.googleSheets.read({
  range: "Sheet1!A1:B2"
});

if (spreadsheet === null) {
  // Handle the null case, e.g., return an empty array
  return [];
} else {
  // Process the spreadsheet data
  return spreadsheet;
}
  1. Configure retry options: If you're experiencing intermittent errors, consider configuring the retry options on the node. You can set the "Retry On Fail" option to true and adjust the "Max Tries" and "Wait Between Tries (ms)" settings as needed.

Prevent it from coming back

To prevent this error from occurring in the future, make sure to:

  • Regularly review and update the spreadsheet range in the node settings.
  • Use null checks and error handling mechanisms, like the one shown in the code block above.
  • Monitor the node's logs and adjust the retry options as needed.

When to escalate

If you've tried the above steps and the error persists, it may be worth escalating the issue to the n8n community or support team. Provide as much detail as possible about the error, including the node settings, spreadsheet data, and any relevant logs. This will help the community or support team to better assist you in resolving the issue.
