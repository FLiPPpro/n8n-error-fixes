n8n workflow HTTP request node 429 Too Many Requests error

Error: 429 Too Many Requests · Node: HTTP Request

What this error actually means

When you encounter the "429 Too Many Requests" error in n8n, it means that the HTTP Request node is sending too many requests to the external API within a certain time frame. This can happen when the API has rate limiting in place to prevent abuse or when your workflow is designed to send a large number of requests in a short period.

The three most common causes

  1. Inadequate retry configuration: If you're not using the retry options on the HTTP Request node or have them set too low, your workflow may not wait long enough for the API to respond, leading to a flood of requests.
  2. Insufficient delay between requests: If you're using the "Wait" node to add a delay between requests, the delay might not be long enough to avoid hitting the rate limit.
  3. Incorrect API key or authentication: If your API key or authentication credentials are incorrect, the API might return a 429 error, even if you're not sending too many requests.

Step-by-step fix

To fix the "429 Too Many Requests" error, follow these steps:

  1. Check the retry configuration:

* Go to the HTTP Request node's Settings tab. * Check if "Retry On Fail" is enabled and the "Max Tries" is set high enough. * If not, enable "Retry On Fail" and increase the "Max Tries" value.

  1. Add a sufficient delay between requests:

* Insert a "Wait" node before the HTTP Request node. * Configure the "Wait" node to wait for a sufficient amount of time (e.g., 1-2 seconds) between requests.

  1. Use the retry options on the HTTP Request node:

* Go to the HTTP Request node's Settings tab. * Configure the "Retry Options" to add a delay between retries (e.g., 1-2 seconds). * Set the "Max Tries" value high enough to allow the API to respond.

  1. Verify the API key or authentication:

* Double-check your API key or authentication credentials. * If using an API key, ensure it's correctly formatted and not expired.

Here's an example code block you can use in a Code node to add a delay between requests:

{
  "nodes": [
    {
      "name": "HTTP Request",
      "parameters": {
        "url": "https://example.com/api/endpoint",
        "method": "GET",
        "headers": {
          "Authorization": "Bearer YOUR_API_KEY"
        }
      },
      "settings": {
        "retryOnFail": true,
        "maxTries": 5,
        "waitBetweenTries": 1000 // 1 second
      }
    },
    {
      "name": "Wait",
      "parameters": {
        "milliseconds": 2000 // 2 seconds
      }
    }
  ]
}

Prevent it from coming back

To prevent the "429 Too Many Requests" error from coming back, make sure to:

  • Monitor your API usage and adjust your workflow accordingly.
  • Regularly review and update your retry configuration and delay between requests.
  • Ensure your API key or authentication credentials are correctly configured and up-to-date.

When to escalate

If you've tried the above steps and the error persists, it's likely due to a more complex issue, such as:

  • The API has rate limiting in place that's not being respected.
  • Your workflow is designed to send an excessive number of requests.
  • There's an issue with your API key or authentication credentials.

In this case, it's recommended to:

  • Consult the API documentation to understand their rate limiting policies.
  • Reach out to the API provider for assistance.
  • Review your workflow design and adjust it to respect the API's rate limits.
