Webhook node returns 404 Not Found error in n8n

Error: 404 Not Found · Node: Webhook

What this error actually means

The 404 Not Found error in n8n's Webhook node indicates that the external service you're trying to send data to is not responding as expected. This could be due to a number of reasons, including a misconfigured URL, a service outage, or a firewall blocking the request.

The three most common causes

1. Incorrect URL

Double-check the URL you've entered in the Webhook node's settings. Make sure it's correct and properly formatted. A common mistake is to forget to include the protocol (http or https) or to use an incorrect domain name.

2. Service Outage

Check the status of the external service you're trying to connect to. If it's down or experiencing issues, you'll need to wait for it to come back online or find an alternative service.

3. Firewall or Network Issues

Verify that there are no firewall rules or network issues blocking the request. You can try using a different network or contacting your IT department to check for any restrictions.

Step-by-step fix

Step 1: Verify the URL

Make sure the URL is correct and properly formatted. You can use a tool like curl to test the URL from the command line:

curl -X GET 'https://example.com/api/data'

Replace https://example.com/api/data with the actual URL you're using in n8n.

Step 2: Add retries to the Webhook node

Configure the Webhook node to retry the request in case of a 404 error. You can do this by going to the node's Settings tab and enabling "Retry On Fail" with a sufficient number of retries (e.g. 3-5) and a reasonable wait time between retries (e.g. 10-30 seconds).

Step 3: Use a "Wait" node to add a delay

If you suspect that the external service is experiencing issues, you can add a "Wait" node to introduce a delay before retrying the request. This can help prevent overwhelming the service with requests.

Step 4: Use a "Code" node to handle errors

Create a "Code" node to handle the 404 error. You can use JavaScript to log the error and retry the request after a certain delay:

const n8n = require('n8n');

exports.onRequest = async (items) => {
  try {
    // Your code here to send the request
  } catch (error) {
    if (error.status === 404) {
      // Log the error and retry the request after 10 seconds
      console.log('Error:', error);
      await new Promise(resolve => setTimeout(resolve, 10000));
      // Retry the request
      return await this.sendRequest(items);
    } else {
      // Handle other errors
    }
  }
};

Prevent it from coming back

To prevent this issue from recurring, make sure to:

  • Regularly check the status of the external service
  • Monitor your n8n logs for any errors or issues
  • Test your Webhook node configuration regularly

When to escalate

If you've tried the above steps and the issue persists, it's likely that there's a more complex issue at play. In this case, you should:

  • Check the n8n documentation and community forums for any known issues or workarounds
  • Reach out to the n8n support team for further assistance
  • Consider escalating the issue to the external service provider or your IT department if necessary
