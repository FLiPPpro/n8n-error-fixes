Webhook node throws 'OAuth2 refresh token revoked' error

Error: OAuth2 refresh token revoked · Node: Webhook

What this error actually means

When you see the "OAuth2 refresh token revoked" error in n8n, it means that the refresh token associated with the OAuth2 connection has been revoked by the OAuth2 provider. This can happen for various reasons, such as:

  • The user has revoked the authorization for the application
  • The OAuth2 provider has revoked the refresh token due to inactivity or other reasons
  • The refresh token has expired

Regardless of the reason, the error indicates that the OAuth2 connection is no longer valid, and you need to take steps to resolve the issue.

The three most common causes

Based on our experience, the three most common causes of this error are:

  1. Token revocation due to user action: The user has revoked the authorization for the application, causing the refresh token to be revoked.
  2. Token expiration: The refresh token has expired, and the OAuth2 provider has revoked it.
  3. Token revocation due to OAuth2 provider settings: The OAuth2 provider has revoked the refresh token due to inactivity or other reasons.

Step-by-step fix

To resolve the issue, follow these steps:

  1. Check the OAuth2 connection: Go to the OAuth2 connection settings and check the "Refresh Token" field. If the token is revoked, you will see an error message.
  2. Re-authorize the application: If the token was revoked due to user action, you need to re-authorize the application. Go to the OAuth2 provider's website and re-authorize the application.
  3. Update the refresh token: If the token was revoked due to expiration, you need to update the refresh token. Go to the OAuth2 connection settings and update the "Refresh Token" field with a new token.
  4. Configure retries: To handle this error, configure the Webhook node to retry the request after a certain delay. You can do this by setting the "Retry On Fail" option to "Yes" and configuring the "Max Tries" and "Wait Between Tries (ms)" options.

Here's an example code block that you can use in a Code node to configure the retries:

{
  "nodes": [
    {
      "name": "Webhook",
      "settings": {
        "retryOnFail": "yes",
        "maxTries": "3",
        "waitBetweenTries": "10000"
      },
      "parameters": {
        "url": "https://example.com/webhook",
        "options": {
          "method": "POST",
          "headers": {
            "Authorization": "Bearer {{OAuth2 Refresh Token}}"
          }
        }
      }
    }
  ]
}

This code block configures the Webhook node to retry the request up to 3 times, with a 10-second delay between retries.

  1. Add a delay: To add a delay between retries, you can use the "Wait" node. Add a "Wait" node after the Webhook node and configure it to wait for a certain amount of time (e.g., 10 seconds).

Prevent it from coming back

To prevent this error from coming back, make sure to:

  • Regularly check the OAuth2 connection settings and update the refresh token as needed.
  • Configure the Webhook node to retry the request after a certain delay.
  • Monitor the workflow logs to detect any issues with the OAuth2 connection.

When to escalate

If you have followed the steps above and the error persists, it may be a sign of a more serious issue with the OAuth2 connection or the workflow configuration. In this case, you should:

  • Check the OAuth2 provider's documentation to see if there are any known issues or restrictions that may be causing the error.
  • Reach out to the n8n community or support team for further assistance.
  • Review the workflow configuration and OAuth2 connection settings to ensure that everything is properly configured.
