Postgres node connection failed error in n8n workflow

Error: Error: Unable to connect to Postgres database: Connection failed · Node: Postgres

What this error actually means

The "Error: Unable to connect to Postgres database: Connection failed" error message indicates that the Postgres node in your n8n workflow is unable to establish a connection to the Postgres database. This error can occur due to various reasons, including incorrect database credentials, network issues, or database downtime.

The three most common causes

Based on our experience, the three most common causes of this error are:

  1. Incorrect database credentials: Double-check that the username, password, host, and port are correct in the Postgres node's settings. Ensure that the credentials are not expired or disabled.
  2. Network issues: Verify that the n8n workflow has a stable network connection to the Postgres database. Check for any firewall rules or network restrictions that might be blocking the connection.
  3. Database downtime: Confirm that the Postgres database is up and running. Check the database's status page or contact the database administrator if you're unsure.

Step-by-step fix

To fix the error, follow these steps:

  1. Check the Postgres node's settings: Go to the Postgres node's settings and verify that the database credentials, host, and port are correct. Make sure to check for any typos or incorrect formatting.
  2. Verify the database credentials: Create a new SQL query in a Code node (JavaScript or Python) to test the database connection. Use the following code as an example:
const { Pool } = require('pg');

const pool = new Pool({
  user: 'your_username',
  host: 'your_host',
  database: 'your_database',
  password: 'your_password',
  port: 5432,
});

pool.query('SELECT 1', (err, res) => {
  if (err) {
    console.error(err);
  } else {
    console.log(res.rows);
  }
});

Replace the placeholders with your actual database credentials. Run this code in a Code node to test the connection.

  1. Check the database logs: If the connection test fails, check the Postgres database logs for any error messages. This can help identify the root cause of the issue.
  2. Retry the connection: If the connection test fails due to a temporary issue, you can add a delay using the "Wait" node to retry the connection. Configure the "Wait" node to wait for a few seconds before retrying the connection.

Prevent it from coming back

To prevent this error from occurring in the future, make sure to:

  1. Regularly test the database connection: Schedule regular tests of the database connection using the Code node to ensure that the credentials and connection settings are correct.
  2. Monitor the database logs: Regularly check the Postgres database logs for any error messages that might indicate a connection issue.
  3. Update the Postgres node settings: If you make any changes to the database credentials or connection settings, update the Postgres node settings accordingly.

When to escalate

If you've followed the steps above and the error persists, it's time to escalate the issue. Contact your database administrator or the n8n support team for further assistance. Provide them with the error message, database credentials, and any relevant logs or configuration files.
