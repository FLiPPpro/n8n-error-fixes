n8n HTTP Request node boolean value error

Error: value is not of expected type · Node: HTTP Request

What this error actually means

The "value is not of expected type" error in the HTTP Request node is a common issue that can be frustrating to resolve. In this article, we'll dive into the possible causes and provide a step-by-step guide to fix the problem.

When you encounter this error, it means that the HTTP Request node is expecting a value of a specific type (e.g., string, number, boolean) in a particular field, but the value being sent is not of that type. This can happen due to various reasons, such as incorrect data type in the input field, unexpected response from the API, or misconfigured node settings.

The three most common causes

Based on our experience, the three most common causes of the "value is not of expected type" error are:

  1. Incorrect data type in the input field: Make sure that the data type in the input field matches the expected type in the HTTP Request node. For example, if the node expects a boolean value, ensure that the input field is set to a boolean value (e.g., true or false).
  2. Unexpected response from the API: If the API returns an unexpected response, it may cause the HTTP Request node to fail. Check the API documentation to ensure that the expected response format is correct.
  3. Misconfigured node settings: Double-check the node settings, especially the "Retry On Fail", "Max Tries", and "Wait Between Tries (ms)" settings. Ensure that the retry options are configured correctly to handle any potential errors.

Step-by-step fix

To fix the "value is not of expected type" error, follow these steps:

  1. Check the input field: Verify that the data type in the input field matches the expected type in the HTTP Request node.
  2. Update the input field: If the data type is incorrect, update the input field to match the expected type.
  3. Use a Code node to validate the data: Create a new Code node and use JavaScript to validate the data type. For example:
const input = {{input}}
if (typeof input !== 'boolean') {
  return { error: 'Invalid input type' }
}

In this code, we're checking if the input value is a boolean. If it's not, we return an error message. You can modify this code to suit your specific needs.

  1. Configure the HTTP Request node: Ensure that the retry options are configured correctly. You can do this by navigating to the HTTP Request node's Settings tab and adjusting the "Retry On Fail", "Max Tries", and "Wait Between Tries (ms)" settings as needed.

Prevent it from coming back

To prevent the "value is not of expected type" error from occurring in the future, follow these best practices:

  1. Use a Code node to validate the data: As mentioned earlier, use a Code node to validate the data type before sending the request.
  2. Configure the HTTP Request node correctly: Ensure that the retry options are configured correctly to handle any potential errors.
  3. Monitor the workflow: Keep an eye on the workflow's performance and adjust the node settings as needed to prevent errors.

When to escalate

If you've followed the steps above and still encounter the "value is not of expected type" error, it's time to escalate the issue. Reach out to your n8n support team or community for further assistance. Provide as much detail as possible about the error, including the node settings, input field values, and any relevant code. This will help the support team to identify the root cause of the issue and provide a more effective solution.
