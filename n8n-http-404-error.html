HTTP Request Node 404 Error Not Found in n8n Workflow

Error: HTTP request failed with status code 404 · Node: HTTP Request

What this error actually means

When you encounter the "HTTP request failed with status code 404" error in n8n, it means that the HTTP Request node was unable to successfully retrieve the resource you're trying to access. A 404 status code is a standard HTTP status code that indicates the requested resource could not be found on the server.

The three most common causes

After analyzing numerous instances of this error, we've identified the following three most common causes:

  1. Incorrect URL: Double-check that the URL you've entered in the HTTP Request node is correct, including the protocol (HTTP or HTTPS), domain, and any path or query parameters.
  2. Server-side issue: The server hosting the resource you're trying to access might be experiencing technical difficulties or might not be configured to handle requests from your domain. Try accessing the resource directly in a web browser to verify if the issue lies with the server.
  3. n8n configuration: Ensure that the HTTP Request node is configured correctly, including the method (e.g., GET, POST), headers, and body. A single misconfiguration can cause the request to fail.

Step-by-step fix

To resolve the issue, follow these steps:

  1. Verify the URL: Double-check the URL in the HTTP Request node. Make sure it's correct, including the protocol, domain, and any path or query parameters.
  2. Add retry options: Configure the HTTP Request node to retry the request in case of a failure. You can do this by:
{
  "retryOnFail": true,
  "maxTries": 3,
  "waitBetweenTries": 5000 // 5 seconds
}

Add this JSON configuration to the HTTP Request node's Settings tab.

Alternatively, you can also configure retry options directly on the node by clicking the "Settings" gear icon and adjusting the "Retry On Fail" settings.

  1. Add a delay: If you suspect that the server-side issue is causing the request to fail, you can add a delay between retries using the "Wait" node. This will give the server time to recover or respond to the request.
  2. Verify the request: Use the "Code" node to log the request details, including the URL, method, headers, and body. This will help you identify if the issue lies with the request itself or with the server-side configuration.

Here's an example Code node configuration that logs the request details:

const request = {
  method: 'GET',
  url: 'https://example.com/api/resource',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    // request body
  })
};

console.log(request);

Prevent it from coming back

To prevent this issue from recurring, consider the following:

  • Regularly review and update the URL in the HTTP Request node to ensure it's correct and up-to-date.
  • Implement a monitoring system to detect and alert you when the request fails.
  • Use the "Error Trigger" to branch on the error and trigger a separate workflow to handle the failure.

When to escalate

If you've tried the above steps and the issue persists, it's likely that the problem lies with the server-side configuration or with the resource you're trying to access. In this case, escalate the issue to the server administrator or the resource owner to investigate and resolve the issue.

Additionally, if you're experiencing frequent or recurring issues with the HTTP Request node, consider implementing a more robust error handling mechanism, such as using the "Error Trigger" to trigger a separate workflow to handle the failure.
