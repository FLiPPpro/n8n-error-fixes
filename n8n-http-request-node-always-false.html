HTTP Request node in n8n always returns false

Error: HTTP Request node always returns false · Node: HTTP Request

What this error actually means

The error message "HTTP Request node always returns false" can be misleading, as it doesn't directly indicate the cause of the issue. However, it suggests that the HTTP Request node is not returning the expected data or is not completing successfully. This can be due to various reasons such as network issues, incorrect API endpoint, or authentication problems.

The three most common causes

Based on common issues, the three most likely causes for this error are:

  1. Incorrect API endpoint: Double-check the API endpoint URL and ensure it's correct. Verify that the endpoint exists and is accessible.
  2. Authentication issues: Ensure that the authentication method (e.g., API key, OAuth) is correctly configured and that the credentials are valid.
  3. Network issues: Check the network connection and ensure that the node can establish a connection to the API endpoint.

Step-by-step fix

To troubleshoot and fix the issue, follow these steps:

  1. Verify the API endpoint: Check the API endpoint URL and ensure it's correct. You can do this by copying the URL and pasting it into a web browser to see if it returns the expected data.
  2. Check authentication: Ensure that the authentication method is correctly configured and that the credentials are valid. You can test this by using a tool like Postman or cURL to make a request to the API endpoint with the same authentication credentials.
  3. Configure retries: If the API endpoint is experiencing temporary issues, you can configure the HTTP Request node to retry the request. To do this, go to the node's Settings tab and enable "Retry On Fail". Set the "Max Tries" to a reasonable number (e.g., 3-5) and the "Wait Between Tries (ms)" to a suitable delay (e.g., 5000-10000).
  4. Use a Code node to add a delay: If you want to add a delay between retries, you can use a "Wait" node to add a delay. Create a new "Wait" node and set the delay to a suitable value (e.g., 5000-10000). Then, connect the "Wait" node to the HTTP Request node.
  5. Use a Code node to handle errors: If the HTTP Request node always returns false, it's likely that the request is failing. You can use a "Code" node to handle errors and provide more detailed information. Create a new "Code" node and add the following JavaScript code:
const error = new n8n.nodes.core.RequestError('HTTP request failed');
return error;

This code creates a new RequestError object with a message indicating that the HTTP request failed. You can then use this error object to handle the failure in your workflow.

Prevent it from coming back

To prevent this issue from recurring, consider the following:

  • Monitor API endpoint: Regularly monitor the API endpoint to ensure it's accessible and returning the expected data.
  • Implement error handling: Implement error handling mechanisms, such as using a "Code" node to handle errors, to provide more detailed information about the failure.
  • Configure retries: Configure retries on the HTTP Request node to handle temporary issues with the API endpoint.

When to escalate

If you've tried the above steps and the issue persists, it's likely that the problem is more complex and requires further investigation. Consider escalating the issue to your team's support or development team for further assistance. Provide detailed information about the issue, including the error message, API endpoint, and any relevant logs or configuration files.
