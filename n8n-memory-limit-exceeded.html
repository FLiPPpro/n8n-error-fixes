n8n "JavaScript heap out of memory" — Fix

Error: FATAL ERROR: JavaScript heap out of memory · Node: n8n core

What this error actually means

The "FATAL ERROR: JavaScript heap out of memory" error is a common issue that occurs when the Node.js process running n8n exhausts its available memory. This can happen when processing large payloads or when the workflow is designed to handle a high volume of data.

In Node.js, the default heap size is set to 1600 MB. When the process reaches this limit, it will throw a "FATAL ERROR: JavaScript heap out of memory" error. This error is not specific to n8n and can occur with any Node.js application.

The three most common causes

There are three common causes of this error:

  1. Large payloads: If your workflow is designed to handle large payloads, such as large JSON files or large CSV files, it can cause the Node.js process to run out of memory.
  2. Inefficient workflow design: If your workflow is designed to process a high volume of data without adequate memory management, it can cause the Node.js process to run out of memory.
  3. Insufficient system resources: If the system running n8n does not have sufficient memory or CPU resources, it can cause the Node.js process to run out of memory.

Step-by-step fix

To fix this error, follow these steps:

  1. Increase the heap size: You can increase the heap size by setting the NODE_OPTIONS environment variable to --max-old-space-size. For example:
export NODE_OPTIONS=--max-old-space-size=2048

This will set the heap size to 2048 MB.

  1. Batch processing: To avoid processing large payloads in a single pass, you can use the "Wait" node to introduce a delay between processing batches of data. For example:
{
  "nodes": [
    {
      "name": "HTTP Request",
      "parameters": {
        "url": "https://example.com/api/data",
        "method": "GET"
      },
      "type": "n8n-nodes-base.httpRequest"
    },
    {
      "name": "Wait",
      "parameters": {
        "milliseconds": 1000
      },
      "type": "n8n-nodes-base.wait"
    }
  ]
}

This will introduce a 1-second delay between processing batches of data.

  1. Configure retry options: To configure retry options for the "HTTP Request" node, follow these steps:

* Go to the "Settings" tab of the "HTTP Request" node. * Configure the "Retry On Fail" option to "true". * Set the "Max Tries" option to the desired number of retries. * Set the "Wait Between Tries (ms)" option to the desired delay between retries.

Prevent it from coming back

To prevent this error from coming back, follow these best practices:

  1. Monitor system resources: Monitor the system resources, including memory and CPU usage, to ensure that they are within acceptable limits.
  2. Optimize workflow design: Optimize the workflow design to minimize memory usage and maximize processing efficiency.
  3. Use batch processing: Use batch processing to avoid processing large payloads in a single pass.
  4. Configure retry options: Configure retry options to handle failures and avoid exhausting system resources.
