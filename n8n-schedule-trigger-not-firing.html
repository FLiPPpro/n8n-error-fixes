n8n Schedule Trigger Not Firing — Fix

Error: workflow does not run on schedule · Node: Schedule Trigger

What this error actually means

When you see the error message "workflow does not run on schedule", it means that n8n is not executing your workflow as planned. This can be due to various reasons, but we'll focus on the three most common causes: Workflow isn't Active, timezone mismatch, or multiple instances racing.

The three most common causes

1. Workflow isn't Active

This is the simplest cause, yet often overlooked. Make sure that the workflow is enabled and set to run on schedule. Check the workflow settings to ensure that the "Enabled" toggle is turned on and the schedule is configured correctly.

2. Timezone mismatch

If your workflow is set to run at a specific time, but your n8n instance is not configured to use the same timezone, the workflow will not run as scheduled. Check your n8n instance's timezone settings to ensure they match the timezone set in the workflow.

3. Multiple instances racing

If you have multiple instances of n8n running, they may interfere with each other's schedules. This can cause workflows to run multiple times, leading to unexpected behavior. Check your n8n instance's settings to ensure that only one instance is running.

Step-by-step fix

To fix the issue, follow these steps:

  1. Check workflow settings:

* Go to the workflow settings and ensure that the "Enabled" toggle is turned on. * Verify that the schedule is configured correctly.

  1. Configure timezone:

* Go to your n8n instance's settings and check the timezone settings. * Ensure that the timezone matches the one set in the workflow.

  1. Check for multiple instances:

* Check your n8n instance's settings to ensure that only one instance is running. * If you have multiple instances, consider setting up a load balancer or a more robust deployment strategy.

  1. Use a Code node to add a delay:

* Create a new Code node and add the following JavaScript code:

const delay = 60000; // 1 minute in milliseconds
return new Promise(resolve => setTimeout(resolve, delay));

* This code will add a 1-minute delay to the workflow. You can adjust the delay value as needed.

  1. Use an Error Trigger to branch on error:

* Create a new Error Trigger and configure it to trigger on workflow errors. * Use the "Continue On Fail" setting to branch on error and continue with the workflow.

Prevent it from coming back

To prevent this issue from coming back, consider the following:

  • Monitor your workflow logs: Regularly check your workflow logs to identify any issues or errors.
  • Use a scheduling library: Consider using a scheduling library like node-schedule to manage your workflows' schedules.
  • Implement retry logic: Use the retry options on the node itself (e.g., HTTP Request node) to implement retry logic.
