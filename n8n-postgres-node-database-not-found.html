Error Database Not Found in n8n Postgres Node

Error: Database not found: invalid_database_name · Node: Postgres

What this error actually means

The Database not found: invalid_database_name error in n8n's Postgres node indicates that the node is unable to connect to the specified database. This error is not related to the Postgres node's connection settings, but rather to the database itself not existing or being inaccessible.

The three most common causes

Based on our experience, the three most common causes of this error are:

  1. Database name typo or misspelling: Double-check that the database name is spelled correctly and matches the one in your Postgres database.
  2. Database not created or not accessible: Verify that the database has been created and is accessible by the Postgres user account used in the n8n workflow.
  3. Postgres user account issues: Ensure that the Postgres user account used in the n8n workflow has the necessary permissions to connect to the database.

Step-by-step fix

To resolve the Database not found: invalid_database_name error, follow these steps:

  1. Verify database name: Check the database name in the Postgres node's settings and ensure it matches the one in your Postgres database. If you're unsure, you can use the psql command-line tool to list all databases:
psql -U postgres -c "SELECT datname FROM pg_database;"

This will list all databases in your Postgres instance. Verify that the database you're trying to connect to is in the list.

  1. Create the database (if necessary): If the database doesn't exist, create it using the psql command-line tool:
psql -U postgres -c "CREATE DATABASE mydatabase;"

Replace mydatabase with the name of the database you want to create.

  1. Grant permissions to the Postgres user account: Ensure that the Postgres user account used in the n8n workflow has the necessary permissions to connect to the database. You can grant permissions using the psql command-line tool:
psql -U postgres -c "GRANT ALL PRIVILEGES ON DATABASE mydatabase TO myuser;"

Replace myuser with the name of the Postgres user account used in the n8n workflow.

  1. Update the Postgres node's settings: Update the Postgres node's settings to use the correct database name and user account.

Prevent it from coming back

To prevent this error from coming back, follow these best practices:

  • Double-check the database name and user account in the Postgres node's settings.
  • Verify that the database has been created and is accessible by the Postgres user account.
  • Grant necessary permissions to the Postgres user account.
  • Consider using a Wait node to introduce a delay between connection attempts, in case the database is temporarily unavailable.

When to escalate

If you've tried the above steps and the error persists, it's likely due to a more complex issue, such as:

  • A Postgres configuration issue
  • A database schema issue
  • A Postgres user account issue

In this case, it's recommended to escalate the issue to a Postgres administrator or a senior developer with experience in Postgres and n8n. They can help investigate and resolve the underlying issue.
