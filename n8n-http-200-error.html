n8n HTTP Request node returns 200 OK but no data

Error: Unexpected end of JSON input · Node: HTTP Request

What this error actually means

The "Unexpected end of JSON input" error in n8n's HTTP Request node occurs when the API response is not a valid JSON object. This can happen for a variety of reasons, including but not limited to:

  • The API is returning an error response that is not in JSON format.
  • The API is returning a response with a different content type than expected (e.g. HTML instead of JSON).
  • The API is returning a response with a malformed JSON object.

The three most common causes

Based on our experience, the three most common causes of this error are:

  1. API returning an error response: If the API is returning an error response, it may not be in JSON format. You can check the API documentation to see if it returns error responses in JSON format.
  2. API returning a response with a different content type: If the API is returning a response with a different content type than expected, the HTTP Request node may not be able to parse it as JSON.
  3. API returning a malformed JSON object: If the API is returning a response with a malformed JSON object, the HTTP Request node may throw an error.

Step-by-step fix

To fix this error, follow these steps:

  1. Check the API documentation: Check the API documentation to see if it returns error responses in JSON format. If it does not, you may need to modify your workflow to handle non-JSON error responses.
  2. Verify the content type: Verify that the API is returning the expected content type (e.g. JSON). You can do this by checking the Content-Type header in the response.
  3. Add a retry mechanism: Add a retry mechanism to your workflow to handle cases where the API returns an error response. You can do this by setting the Retry On Fail option to true on the HTTP Request node.
  4. Add a delay: Add a delay to your workflow to allow the API to recover from temporary errors. You can do this by adding a Wait node to your workflow.

Here is an example of how you can add a retry mechanism to your workflow:

{
  "nodes": [
    {
      "name": "HTTP Request",
      "type": "http-request",
      "settings": {
        "retryOnFail": true,
        "maxTries": 3,
        "waitBetweenTries": 1000
      }
    }
  ]
}

You can also add a delay to your workflow by adding a Wait node:

{
  "nodes": [
    {
      "name": "HTTP Request",
      "type": "http-request"
    },
    {
      "name": "Wait",
      "type": "wait",
      "settings": {
        "duration": 1000
      }
    }
  ]
}
  1. Verify the JSON response: Verify that the API is returning a valid JSON response. You can do this by checking the response field of the HTTP Request node.

Prevent it from coming back

To prevent this error from coming back, follow these best practices:

  • Verify the API documentation: Make sure you understand how the API handles error responses and what content types it returns.
  • Use a retry mechanism: Use a retry mechanism to handle cases where the API returns an error response.
  • Add a delay: Add a delay to your workflow to allow the API to recover from temporary errors.
  • Verify the JSON response: Verify that the API is returning a valid JSON response.

When to escalate

If you have tried the above steps and the error persists, it may be necessary to escalate the issue to the API provider or a developer. Be sure to provide as much information as possible about the error, including:

  • The API endpoint being called
  • The request method (e.g. GET, POST, etc.)
  • The request headers
  • The request body
  • The response headers
  • The response body

This will help the API provider or developer to diagnose and fix the issue.
