Merge Node Error - Missing Key

Error: Merge node outputs fewer items than inputs (missing key) · Node: Merge

What this error actually means

The error "Merge node outputs fewer items than inputs (missing key)" is a common issue in n8n workflows. It occurs when the Merge node is unable to combine data from multiple inputs due to a missing key. This key is used to identify and merge matching records from different inputs.

In essence, the error is telling you that the Merge node is not able to find a common key to merge the data on. This can happen when the data from different inputs does not have a matching key, or when the key is not properly configured in the Merge node.

The three most common causes

Based on our experience, the three most common causes of this error are:

  1. Missing key configuration: The key used to merge data is not properly configured in the Merge node. This can happen when the key is not selected, or when the key is not correctly formatted.
  2. Data inconsistency: The data from different inputs does not have a matching key. This can happen when the data is not properly formatted, or when the key is not consistently used across different inputs.
  3. Incorrect data type: The data type of the key is not consistent across different inputs. This can happen when the key is a string in one input, but an integer in another input.

Step-by-step fix

To fix this error, follow these steps:

  1. Check the key configuration: Go to the Merge node and check if the key is properly configured. Make sure the key is selected and correctly formatted.
  2. Check data consistency: Check the data from different inputs to ensure that the key is consistently used. If the data is not consistent, you may need to modify the data before it reaches the Merge node.
  3. Check data type: Check the data type of the key in different inputs. If the data type is not consistent, you may need to convert the data type before it reaches the Merge node.

Here is an example of how you can check the key configuration and data consistency using JavaScript in a Code node:

const data = [
  { id: 1, name: 'John' },
  { id: 2, name: 'Jane' },
  { id: 3, name: 'Bob' }
];

const key = 'id';

const mergedData = data.reduce((acc, curr) => {
  if (!acc.find(item => item[key] === curr[key])) {
    acc.push(curr);
  }
  return acc;
}, []);

console.log(mergedData);

This code checks if the key is consistently used across different inputs. If the key is not consistently used, the code will not merge the data.

Prevent it from coming back

To prevent this error from coming back, make sure to:

  • Regularly check data consistency: Regularly check the data from different inputs to ensure that the key is consistently used.
  • Use a consistent data type: Use a consistent data type for the key across different inputs.
  • Use a backup key: Use a backup key in case the primary key is missing.

When to escalate

If you have tried the above steps and the error still persists, it may be time to escalate the issue. This can happen when:

  • Data is complex: The data is complex and requires a custom solution.
  • Data is inconsistent: The data is inconsistent and requires manual intervention.
  • Key is missing: The key is missing and cannot be recovered.

In this case, it is recommended to reach out to the n8n community or support team for further assistance.
