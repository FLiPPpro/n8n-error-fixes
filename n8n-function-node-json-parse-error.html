n8n Function/Code Node JSON Parse Error — Fix

Error: SyntaxError: Unexpected token in JSON · Node: Code

What this error actually means

When you encounter the SyntaxError: Unexpected token in JSON error in n8n, it means that the upstream response is not valid JSON. This can happen for several reasons, including:

  • The upstream server is returning an HTML error page instead of JSON data.
  • The upstream response contains a trailing comma, which is not valid JSON.
  • The upstream server is using chunked encoding, which can cause issues with JSON parsing.

The three most common causes

Based on our experience, the three most common causes of this error are:

  • Upstream server returning HTML error page: This can happen when the upstream server is configured to return an HTML error page instead of JSON data. This can be due to a misconfiguration or a bug in the upstream server.
  • Trailing comma in upstream response: This can happen when the upstream server is returning a JSON object with a trailing comma. This is not valid JSON and can cause parsing errors.
  • Chunked encoding in upstream response: This can happen when the upstream server is using chunked encoding to send the response. This can cause issues with JSON parsing, especially if the chunks are not properly formatted.

Step-by-step fix

To fix this error, you need to add a try-catch block in your Code node to catch the SyntaxError exception. You also need to check the Content-Type header of the upstream response to ensure it's set to application/json. Here's an example code block that you can use:

const response = await fetch('https://example.com/api/data');
if (response.ok) {
  const contentType = response.headers.get('Content-Type');
  if (contentType === 'application/json') {
    try {
      const data = await response.json();
      // Process the data here
    } catch (error) {
      if (error instanceof SyntaxError) {
        // Handle the error here
      } else {
        // Handle other errors here
      }
    }
  } else {
    // Handle non-JSON response here
  }
} else {
  // Handle non-200 response here
}

In this code block, we first check if the upstream response is OK (200-299). We then check the Content-Type header to ensure it's set to application/json. If it is, we try to parse the response as JSON using the response.json() method. If the parsing fails, we catch the SyntaxError exception and handle it accordingly.

Prevent it from coming back

To prevent this error from coming back, you need to ensure that the upstream server is configured to return valid JSON data. This may involve:

  • Configuring the upstream server to return JSON data instead of HTML error pages.
  • Fixing any issues with the upstream server that may be causing trailing commas in the response.
  • Configuring the upstream server to use a different encoding scheme, such as chunked encoding.

You should also consider adding retries to your workflow to handle cases where the upstream server is down or responding slowly. You can configure retries on the HTTP Request node by setting the Retry On Fail option to true and specifying the Max Tries and Wait Between Tries (ms) options.

When to escalate

If you've tried the above steps and the error persists, it may be worth escalating the issue to your upstream server administrators or developers. They may be able to provide more information about the upstream server configuration or help you troubleshoot the issue. Additionally, if you're using a third-party API or service, you may want to check their documentation or support resources for any known issues or workarounds.
