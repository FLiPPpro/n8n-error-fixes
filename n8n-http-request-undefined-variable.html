HTTP Request Node Error: TypeError: Cannot read properties of undefined

Error: TypeError: Cannot read properties of undefined (reading 'X') · Node: HTTP Request

What this error actually means

When you encounter the TypeError: Cannot read properties of undefined (reading 'X') error in n8n, it means that the HTTP Request node is trying to access a property (X) of an undefined variable. This is a common issue when working with variables in n8n, especially when trying to send requests with dynamic values.

The three most common causes

After analyzing numerous reports of this error, I've identified the following three most common causes:

  1. Variable not defined: The variable being referenced in the HTTP Request node is not defined in the workflow. This can happen when a variable is not set or is not available in the current scope.
  2. Incorrect variable name: The variable name being used in the HTTP Request node is incorrect or does not match the actual variable name.
  3. Variable not populated: The variable being referenced in the HTTP Request node is not populated with a value, causing the error when trying to access its properties.

Step-by-step fix

To fix this error, follow these steps:

  1. Verify variable definition: Check that the variable being referenced in the HTTP Request node is defined in the workflow. You can do this by checking the Variables tab in the workflow settings.
  2. Check variable name: Double-check that the variable name being used in the HTTP Request node matches the actual variable name.
  3. Populate variable: Ensure that the variable being referenced in the HTTP Request node is populated with a value. You can do this by adding a Set node to populate the variable with a value.
  4. Use the correct syntax: Make sure to use the correct syntax when referencing the variable in the HTTP Request node. Use the {{ }} syntax to reference variables, like this: {{variableName}}.

Here's an example code block that demonstrates how to populate a variable with a value and then use it in the HTTP Request node:

// Set node to populate variable
{
  "name": "Set Variable",
  "parameters": {
    "variable": "myVariable",
    "value": "Hello, World!"
  },
  "type": "Set"
}

// HTTP Request node with variable reference
{
  "name": "HTTP Request",
  "parameters": {
    "method": "GET",
    "url": "https://example.com",
    "headers": {
      "Authorization": "Bearer {{myVariable}}"
    }
  },
  "type": "http-request"
}

In this example, the Set node populates the myVariable variable with the value "Hello, World!". The HTTP Request node then references this variable using the {{myVariable}} syntax.

Prevent it from coming back

To prevent this error from coming back, make sure to:

  • Verify that the variable is defined and populated with a value before using it in the HTTP Request node.
  • Use the correct syntax when referencing variables.
  • Test your workflow thoroughly to catch any errors.
